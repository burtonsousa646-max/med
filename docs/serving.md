# Показ, клики, результаты, расчёты

Код — `server/modules/serving.ts` (выбор рекламы), `tracking.ts` (показы, клики, результаты), `settlement.ts` (деньги по событиям), `reporting.ts` (статистика). Тесты — `serving.test.ts`. Контракт — `api/public.yaml` (теги «показ», «результаты»), `api/cabinet.yaml` (теги «статистика», «результаты»).

## 1. Как поверхность показывает рекламу

```
поверхность                       платформа
    │ POST /api/public/serve {placement, medId?, lat?, lon?}
    │──────────────────────────────►│ индекс → фильтры → скор → аукцион
    │◄── ads[]: креатив, erid,  ────│
    │    impressionUrl, clickUrl    │
    │ карточка видна наполовину      │
    │ POST impressionUrl ───────────►│ показ записан (повтор — нет)
    │ абонент нажал                  │
    │ GET clickUrl ─────────────────►│ click_id, правила оплаты
    │◄── 302 на сайт партнёра ───────│     ?utm_…&click_id=bl…
    │    (или JSON для приложения)   │
```

Ссылки показа и клика содержат подписанный токен (HMAC, секрет `SERVE_SECRET`): ID показа, кампания, креатив, место, цена клика из аукциона, MED-ID, время выдачи. Токен живёт 24 часа. Подделать цену или кампанию нельзя.

**Ключ поверхности.** Если на сервере задан `SURFACE_KEYS=app:ключ,site:ключ`, запрос показа без заголовка `X-Surface-Key` с одним из ключей отклоняется (401). Не задан — показ без ключа (разработка, эталонная витрина).

**CORS.** `/api/public/*` отвечает любому домену: его зовут сайты билайна, cookie здесь не используются.

## 2. Выбор рекламы

Индекс живых кампаний — в памяти процесса, перечитывается раз в 5 секунд одним запросом: кампания, последний одобренный и промаркированный креатив, точки, остаток денег компании, траты за сегодня и за месяц, накопленные показы и клики. На запрос показа база не трогается.

**Фильтры** — по порядку:

| Фильтр | Правило |
|---|---|
| место | кампания выбрала это место показа |
| расписание | между `startsAt` и `endsAt`, если заданы |
| деньги | кроме купона и подписки: остаток (основной + бонусы) больше нуля (крупному бизнесу — постоплата), не исчерпан дневной лимит и месячный бюджет |
| гео | если поверхность передала координаты — абонент в радиусе кампании (по умолчанию 1 км) хотя бы от одной активной точки |
| частота | не больше 3 показов кампании одному абоненту за 7 дней |
| согласие | MED-ID без согласия на рекламу (порт `consents`) — пустой ответ |
| сигналы | если передан MED-ID: «кроме» — ни один не совпал; «и» — все совпали; «любой из» — хотя бы один (порт `dmp`). Без MED-ID — показ по контексту, сигналы не проверяются |
| одна от компании | две кампании одной компании в одном ответе не появятся |

**Скор** = ставка за клик × pCTR.
- Ставка «перехода» — ставка кампании или автоставка: полторы минимальных (минимальная — самая высокая из места показа и выбранных сигналов, тиры T1–T4).
- У оплаты за результат ставка за клик ожидаемая: цена результата × доля кликов, ставших результатом (`settings.result_rate`). Заявка — цена заявки; заказ — чек × процент; купон и подписка — доля билайна с платежа. Минимальная ставка за клик к ним не применяется: за клик они не платят.
- Широкая карточка — плюс наценка (`wide_card_markup_pct`, 30 %).
- pCTR — априорный CTR места, сглаженный наблюдаемым CTR кампании: (клики + CTR места × 200) / (показы + 200). Новая кампания стартует с CTR места, по мере показов вес переходит к её собственному.

**Аукцион** — обобщённая вторая цена: победитель платит столько, чтобы его скор сравнялся со скором следующего, плюс 1 копейка, но не ниже минимальной ставки и не выше своей ставки. Единственный участник платит минимальную ставку. Число мест — `placements.slots` (в витрине 6).

Собственные офферы билайна с теневой ставкой «конверсия × маржа» — когда появятся в каталоге: в аукционе для них место предусмотрено, своих кампаний билайна пока нет.

## 3. Клики

`GET /api/public/c/<token>` создаёт `click_id` (`bl` + 16 случайных символов) и пишет клик. Клик **оплачивается**, только если это «переход» и:

| Не оплачивается | Причина в `clicks.reason` |
|---|---|
| антифрод (порт `adtech`) оценил клик как бота, 0,9 и выше | `fraud` |
| прошло меньше 0,5 с от выдачи рекламы | `tooFast` |
| тот же абонент уже оплатил клик по этой кампании за 24 часа | `repeat24h` |

Цена клика — из аукциона, зашита в токен. Ответ — редирект на сайт партнёра с `utm_source=beeline`, `utm_medium=<тип>`, `utm_campaign=<id>` и `click_id`. Для приложения — `?format=json`: `{ clickId, url }`.

## 4. Результаты

| Тип | Откуда результат | Статус сразу | Спор |
|---|---|---|---|
| заявка | форма в приложении (`POST /public/act/<click_id>` с телефоном) или сервер партнёра | ждёт | 7 дней |
| заказ по промокоду | сервер партнёра (постбэк) или файл CSV, с суммой | ждёт | 14 дней |
| купон | оплата со счёта телефона (`POST /public/act/<click_id>`, порт `subscriberBilling`) | засчитан | нет |
| подписка | то же | засчитана | нет |

**Постбэк**: `GET /api/public/postback?key=…&click_id=…&order_id=…&status=…&amount=…`. Ключ — из «Подключений», хранится хеш, ключей может быть несколько. `click_id` должен принадлежать компании ключа. Повтор с тем же `order_id` меняет статус, дубля нет. Разрешённые переходы: ждёт → засчитан / отклонён; засчитан → возврат. Обратно — 422.

**CSV**: `click_id;order_id;status;amount`, разделитель `;` `,` или табуляция, первая строка может быть заголовком. Ошибочные строки пропускаются и перечисляются в ответе.

**Спор** — в кабинете: засчитать или оспорить до срока. Не оспоренные к сроку засчитываются сами (воркер раз в 10 минут). Оплату со счёта телефона партнёр не оспаривает: её подтверждает биллинг.

Заявка из формы сразу уходит партнёру письмом с именем и телефоном — с согласия абонента, которое он даёт, отправляя форму.

## 5. Деньги по событиям

Воркер раз в минуту:

| Что | Проводки |
|---|---|
| оплачиваемые клики кампании старше 10 с — одной операцией | бонусы и основной счёт партнёра → выручка билайна |
| засчитанная заявка — цена заявки | то же |
| засчитанный заказ — сумма × процент | то же |
| возврат заказа после списания | выручка → основной счёт партнёра |
| засчитанный купон или подписка | платёж абонента: доля билайна → выручка, остальное → счёт выплат партнёра |
| возврат по купону или подписке | сторно счёта выплат |

Событие и операция пишутся в одной транзакции (`charge_tx_id`), поэтому повтор не списывает дважды.

**Выплаты.** Первого числа (или финансист — `POST /admin/payouts/run { period }`) остаток счёта выплат каждой компании становится выплатой за прошлый месяц и уходит в учётную систему (порт `accounting.requestPayout`) на её расчётный счёт. Без реквизитов — `failed`, деньги ждут на клиринге. Партнёр получает письмо.

**Пейсинг.** Отдельного сервиса нет: индекс показа видит траты за день и месяц (включая ещё не списанные клики) и остаток денег и перестаёт показывать кампанию в пределах 5 секунд. Перерасход ограничен кликами, сделанными за эти секунды.

## 6. Статистика

Воркер раз в минуту пересчитывает почасовые свёртки за последние 3 часа (`stats_hourly`): показы, охват, клики, оплачиваемые клики, результаты, траты на клики по месту показа. `GET /cabinet/campaigns/{id}/stats?from&to` — итоги за период (по умолчанию 14 дней), клики по часам за 48 часов, показы по дням, разбивка по местам. Результаты и деньги за результаты считаются по событиям, а не по свёрткам: статус результата меняется через дни, а свёртка по часу создания этого не увидит.

**ОРД.** Первого числа — статистика за прошлый месяц по каждому erid и месту показа: показы и деньги (порт `ord.reportStats`).

## 7. Поверхности

- **Витрина «лучшее рядом»** — `/near` в интерфейсе, эталон для приложения: запрос показа с ID устройства и, по кнопке, координатами; показ засчитывается, когда карточка видна наполовину; переход и промокод — на сайт партнёра, купон и подписка — оплата со счёта телефона, заявка — форма.
- **embed.js** — для сайтов билайна без сборки:

```html
<div data-beeline-ads data-placement="main" data-limit="2"></div>
<script src="https://<платформа>/embed.js" data-surface-key="<ключ>" async></script>
```

Пример — `/embed-demo.html`.

## 8. Нагрузка

`npm run load` — `scripts/load.ts`: запросы показа с заданной параллельностью, маяк показа на каждый, клик на каждый десятый. Замер 30.10.2026 на ноутбуке разработчика (один процесс API, локальный PostgreSQL), 3 000 запросов, 50 параллельно:

| | p50 | p95 | p99 |
|---|---|---|---|
| показ | 3,0 мс | 6,4 мс | 18,8 мс |
| клик | 7,0 мс | 10,9 мс | 15,1 мс |

Около 6 900 запросов показа в секунду. Цель плана — p95 до 50 мс — с запасом.

На стенде (platform.napovtor.ru, общий VPS) 30.10.2026, 1 000 запросов, 20 параллельно, замер с компьютера разработчика — то есть вместе с дорогой по интернету: p50 14,2 мс, p95 22,1 мс, p99 75,3 мс, около 1 200 в секунду. Живых кампаний на стенде ещё не было, ответы пустые — замер показывает путь запроса, а не аукцион.

## 9. Потолки и что дальше

| Сейчас | Потолок | Когда менять |
|---|---|---|
| частота — счётчик в памяти процесса | при нескольких экземплярах API каждый видит свои показы | вместе со вторым экземпляром: Redis или выборка из `impressions` |
| индекс в памяти, перечитывается раз в 5 с | при тысячах кампаний перечитывание тяжелеет | инкрементальное обновление по событиям кампаний |
| pCTR — сглаженный CTR | не учитывает абонента и контекст | модель Big Data через порт `dmp` |
| места показа cpm (ТВ) — без списаний за показы | кампаний на ТВ пока нет | когда ТВ войдёт в продажу |
