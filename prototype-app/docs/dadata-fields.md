# Поля DaData: сохранение, письмо менеджеру и админка

Партнерская платформа билайн. Состав полей проверен по локальному коду 19 ноября 2026 года.

## Данные из реестра

При поиске по ИНН сохраняем снимок данных DaData на сервере. При отправке заявки прикрепляем к ней снимок по указанному ИНН, полученный не более семи дней назад. Эти данные используются в письме менеджеру и в карточке заявки в админке. Если при отправке снимка не было, карточка сотрудника запрашивает реквизиты по ИНН заявки при открытии. После успешного поиска сервер сохраняет их с фактической датой проверки. При повторном открытии сотрудник видит тот же снимок.

| Поле | Ключ | Содержание и особенности |
|---|---|---|
| ИНН | `business.inn` | Идентификатор компании или ИП, по которому выполнен поиск. Используется для связи со снимком реестра. |
| Полное наименование | `registryDetails.legalName` | Полное наименование по реестру. Для ИП при отсутствии полного наименования используется название из результата поиска. |
| КПП | `registryDetails.kpp` | Для юридических лиц; для ИП не показывается. |
| ОГРН / ОГРНИП | `registryDetails.ogrn` | Регистрационный номер юридического лица или ИП. |
| Адрес по реестру | `registryDetails.legalAddress` | Юридический адрес / адрес регистрации. Не считается автоматически подтверждённой точкой продаж. |
| Руководитель по реестру | `registryDetails.manager` | ФИО руководителя; для ИП не показывается. |
| Должность руководителя | `registryDetails.managerRole` | Должность по реестру; для ИП не показывается. |
| Основной ОКВЭД | `registryDetails.okved` | Код основного вида деятельности. |
| Дата проверки | `registryDetails.checkedAt` | Время получения данных. В письме и админке отображается по московскому времени. Формируется нашей системой. |
| Требуется проверка | `registryDetails.requiresReview` | Признак замечаний к данным организации или адресу. Формируется нашей системой по ответу DaData и при наличии отображается рядом с датой проверки. |

В письме менеджеру и админке реквизиты выводятся в блоке «Реквизиты для партнёрского договора», ИНН — в блоке сведений о бизнесе. Оба представления используют общий набор строк.

## Поля профиля бизнеса

DaData также заполняет поля профиля. Пользователь может изменить их перед отправкой; в заявке, письме менеджеру и админке используются итоговые значения.

| Поле | Ключ | Источник |
|---|---|---|
| Название бизнеса | `business.name` | Краткое наименование с организационно-правовой формой; при отсутствии — название из результата поиска или полное наименование. |
| Сфера деятельности | `business.category` | Название основного вида деятельности; при отсутствии — категория из внутреннего справочника по ОКВЭД. |
| Город бизнеса | `business.city` | Город, населённый пункт или регион из адреса. |
| Сайт | `business.website` | Первый подходящий сайт из ответа DaData, если он есть. |

Для автозаполнения также возвращаются адрес `registeredAddress` и источник `source: "dadata"`. В блоке реестровых реквизитов используется отдельное поле `registryDetails.legalAddress`; адреса точек продаж подтверждаются пользователем отдельно.

## Данные, которые получаем отдельно от партнёра

Следующие поля не извлекаются из DaData в текущей интеграции:

- Имя представителя и контактный телефон.
- Email, подтверждаемый кодом.
- ФИО подписанта, его должность и основание полномочий.
- Банк, БИК, расчётный и корреспондентский счета.
- Реквизиты, которые партнёр дополнительно указал или исправил вручную.

Реквизиты, введённые вручную, отображаются с пометкой «Со слов партнёра», отдельно от снимка реестра.

## Если данных нет

- Отсутствующее поле реестра отображается как «Нет данных».
- При отсутствии актуального снимка отображается «Нет снимка реестра. Требуется проверка».
- При ответе DaData со статусом бизнеса, отличным от `ACTIVE`, поиск возвращает сообщение о необходимости проверки, а сохранённый снимок по этому ИНН удаляется.
