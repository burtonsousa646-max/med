# Бэкофис и уведомления

Код — `server/modules/backoffice.ts` (API), `web/src/admin/Admin.tsx` (экраны, адрес `/admin`), `server/modules/notifications.ts`. Тесты — `backoffice.test.ts`, `notifications.test.ts`. Контракт — `api/admin.yaml`.

## 1. Роли и разделы

Сотрудник входит через корпоративный SSO, роли приходят из него при каждом входе. Раздел виден, только если у сотрудника есть роль; права всё равно проверяет сервер. `admin` видит всё.

| Раздел | Роли | Что можно |
|---|---|---|
| обзор | все | выручка за день и месяц, показы и клики за сегодня, живые кампании, очереди «ждут людей», адаптеры портов |
| модерация | moderator | одобрить или отклонить с причиной; одобренное уходит в ОРД |
| партнёры | manager, finance, moderator | поиск по ИНН и названию, карточка: реквизиты и проверка, деньги, люди, кампании, связи с внешними системами |
| — проверка юрлица | manager | «проверена», «отказ» с причиной, «заблокировать» с причиной |
| — корректировка баланса | finance | зачислить или списать с причиной |
| кампании | manager, moderator, finance | список по статусам с тратами за месяц; «остановить» с причиной (manager, moderator) |
| финансы | finance | итоги счетов, неоплаченные счета («оплачен»), поступления без счёта, выплаты, «закрыть месяц», «выплаты за месяц» |
| спецпроекты | manager | заявки партнёров: в работе, сделано, отказ |
| справочники | admin | места показа (минимальная ставка, CTR, мест в слоте, включено); параметры платформы с проверкой границ |
| интеграции | admin | очередь (упавшие задачи — «повторить»), журнал вызовов и событий по системам |
| журнал | admin | последние 300 действий партнёров, сотрудников и системы |

**Блокировка компании** ставит её живые кампании на паузу и сразу убирает из показа. Индекс показа берёт только проверенные компании, поэтому партнёр не вернёт кампанию в показ, сняв её с паузы. **Остановка кампании** её завершает: партнёр не может её возобновить и получает причину.

Изменения мест показа и параметров показ видит сразу: индекс перечитывается принудительно.

## 2. Уведомления партнёру

Модуль кладёт событие в очередь в своей транзакции. Получатели, каналы и текст выбираются при отправке.

| Событие | Когда | Кому | SMS |
|---|---|---|---|
| `campaign_live` | кампания прошла проверку и получила erid | владелец, сотрудники | да |
| `creative_rejected` | текст не прошёл проверку или кампанию остановили | владелец, сотрудники | да |
| `new_lead` | заявка из формы в приложении | владелец, сотрудники | да |
| `low_balance` | денег меньше чем на 3 дня трат живых кампаний; не чаще раза в сутки | + бухгалтер | да |
| `payout` | выплата за месяц отправлена | + бухгалтер | нет |
| `login_code`, `invitation`, `approval_request` | вход, приглашение, ссылка руководителю | адресат | — |

Каналы — по настройкам компании (`notify`): почта участникам, SMS на телефон компании. Telegram в настройках есть, но шлём в него, только когда появится привязка чата. Тексты — в `TEMPLATES`. Адаптер почты или SMS билайна берёт готовый текст из `render()`, а не собирает его сам.

На стенде порт `messaging` — заглушка: письма никуда не уходят. Поэтому вход по коду на почту на стенде не работает, входите через бизнес-ID (заглушку провайдера).
