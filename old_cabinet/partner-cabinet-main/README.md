# МЁД — Кабинет партнёра (фронтенд-прототип)

Продвинутый интерактивный прототип личного кабинета партнёра платформы **МЁД** (Билайн) и внутренней админки (КАМ/модератор/финансы). Собран поверх материалов `../MED_HANDOFF/` и двух исходных демо-прототипов.

## Что это — и что нет

**Это** — фронтенд-приложение с реалистичной клиентской автоматизацией: валидация форм, стейт-машины с честным отклонением недопустимых переходов, идемпотентность мутаций, построчные расчёты вместо плоского процента. Все данные хранятся в `localStorage` браузера.

**Это не** — не настоящий backend, не production-система, не подключение к реальным системам Билайна (Mobile ID, CVM, платёжный провайдер). Роли переключаются локально через демо-логин — это не реальная авторизация. Смотрите `MED_HANDOFF/14_DECISIONS_AND_OPEN_QUESTIONS.md` для списка открытых решений, которые нельзя реализовать без владельцев соответствующих систем.

## Запуск

```bash
npm install
npm run dev       # dev-сервер (Vite)
npm run test      # unit-тесты (стейт-машины, seed-данные)
npm run build     # production-сборка
npm run lint      # oxlint
```

## Демо-вход

На `/login` выберите одну из демо-ролей (партнёр или сотрудник Билайна). Роль также можно переключить через меню в правом верхнем углу кабинета — это позволяет провести полный цикл «партнёр отправил → сотрудник одобрил» в одной сессии браузера.

## AI-функции (GPT / DALL·E)

AI-помощник, генерация текста оффера и иконки оффера работают через собственные serverless-эндпоинты (`api/assistant.ts`, `api/offers/generate-copy.ts`, `api/icons/generate.ts`). Ключ OpenAI читается только на сервере из `process.env.OPENAI_API_KEY` и никогда не попадает в код, отдаваемый браузеру (проверено — `grep` по production-сборке не находит ни ключа, ни `api.openai.com`).

**Локально**: скопируйте `.env.example` в `.env.local`, впишите свой ключ, перезапустите `npm run dev`. Без ключа функции работают в честном деградированном режиме: помощник переключается на встроенный FAQ, конструктор оффера показывает понятную ошибку вместо падения.

**На Vercel** (чтобы партнёр открывал кабинет по публичной ссылке):
```bash
npm i -g vercel      # один раз, если ещё не установлен
cd med-cabinet
vercel               # логин через браузер, первый деплой (preview-ссылка)
vercel env add OPENAI_API_KEY production   # вставить ключ, когда попросит
vercel --prod        # продакшен-деплой с постоянной ссылкой
```
`vercel.json` уже настроен на SPA-роутинг (все пути, кроме `/api/*`, отдают `index.html`), Vercel сам определит `api/*.ts` как serverless-функции — дополнительная конфигурация не нужна.

## Сброс демо-данных

Данные детерминированно генерируются при первом запуске (`src/mock-api/db/seed.ts`) и живут в `localStorage['med-cabinet-db-v1']`. Чтобы начать заново:

```js
// в консоли браузера
localStorage.removeItem('med-cabinet-db-v1')
localStorage.removeItem('med-cabinet-session')
localStorage.removeItem('med-cabinet-onboarding')
location.reload()
```

## Структура

- `src/design-system/` — токены Carnica (цвета/типографика/радиусы), перенесённые из публичной базы знаний дизайн-системы Билайн
- `src/components/` — переиспользуемые UI-примитивы (Button, StatusPill, Modal с focus-trap, Stepper, DataTable-подобные таблицы)
- `src/mock-api/` — типизированный mock-слой: `types/` (каноническая модель), `state-machines/` (guard-таблицы), `resources/` (аналог REST-эндпоинтов), `db/` (seed + персистентность)
- `src/pages/` — экраны по разделам (onboarding, offers, orders, settlements, admin и т.д.)
- `src/hooks/` — обёртки React Query над mock-api

## Известные ограничения (честно, не скрыто)

- Бандл `dist/assets/index-*.js` ~1 МБ — для демо не критично, но перед production нужен code-splitting по маршрутам
- Шрифт BeelineSans не встроен (проприетарный) — используется системный fallback из тех же токенов
- Accessibility-проход (полный keyboard-QA по всем модалям, `aria-*` аудит) сделан частично — фокус-трап в Modal есть, но не покрыт автоматическими тестами
- Sandbox/интеграция — упрощённая имитация, не воспроизводит реальные сетевые сбои/ретраи из RFC05
