# Рекламная платформа билайна: прототип кабинета партнёра

Лендинг и кабинет партнёра по CJM 2.0. Стили берутся из `../design-system` (токены и компоненты `bl-`), своих цветов нет.

Всё для разработчиков в одном файле — [Документация для разработки.md](Документация%20для%20разработки.md).

Подход API first: всё, что кабинет показывает и меняет, идёт через один контракт `api/openapi.yaml`. Тестовый сервер в `server/` реализует его поверх SQLite, чтобы прототип работал по-настоящему. Разработчики пишут бэкенд по тому же контракту, а интерфейс переключается на него одной переменной.

## Запуск

Для запуска в контейнерах и переноса на сервер используйте [Docker-инструкцию](deploy/README.md): контейнеры интерфейса, API и Autocomplete, постоянный том SQLite, варианты с существующим nginx или автоматическим HTTPS, перенос образов, резервное копирование и откат. На главной странице `/` открывается лендинг v4. Ссылка `/#/v4` также работает.

V4 сохраняет введённые данные и файлы в IndexedDB. После принятия оферты черновик
также обновляется в SQLite. «Завершить настройку» сохраняет отдельную заявку и
ставит письмо в очередь. Экран успеха подтверждает приём заявки сервером.

Письма с заявками и вложениями отправляются на `beepartners@beeline.ru` через SMTP Yandex Cloud Postbox.
Укажите `CAMPAIGN_MAIL_FROM` и `CAMPAIGN_SMTP_USER`. Для локального запуска API задайте
`CAMPAIGN_SMTP_PASSWORD_FILE` с путём к файлу пароля вне репозитория. Для сервера
используйте systemd credential или Docker Compose secret по [инструкции](deploy/README.md#отправка-заявок-v4-через-smtp).
При ошибке письма остаются в `v4_submissions` для повторной отправки. Столбец `mail_sent_at`
заполняется после того, как SMTP-сервер принял письмо в очередь.
Если API стоит за nginx, разрешите тело запроса до 11 МиБ для двух изображений.


Нужен Node 22.18 или новее: в нём есть встроенная SQLite и запуск TypeScript без сборки (`nvm use` возьмёт версию из `.nvmrc`).

```bash
npm install
npm run dev
```

`npm run dev` поднимает интерфейс на http://127.0.0.1:5173, API на порту 8787 и Autocomplete на порту 8788. Vite направляет запросы к нужному сервису.

| Команда | Что делает |
|---|---|
| `npm run dev` | API, Autocomplete и интерфейс вместе, с перезапуском при правках |
| `npm run autocomplete` | Только Autocomplete на порту 8788 |
| `npm run server` | только API (порт — переменная `API_PORT`, база — `DB_PATH`, по умолчанию `server/demo.sqlite`) |
| `npm test` | сквозная проверка API: вход, сборка, оплата, запуск, подтверждение руководителем, выплаты, отслеживание (ключ, повторы order_id, спор, CSV), ошибки |
| `npm run api:types` | пересобрать `src/api.gen.ts` из контракта. Запускать после каждой правки `openapi.yaml` |
| `npm run build` | проверка типов и сборка интерфейса в `dist/` |

## Как устроено

### Autocomplete для настройки кампании

После ввода корректного ИНН фронт вызывает `POST /api/autocomplete/inn`.
В запросе к DaData передаётся только ИНН. Название, город, сфера и сайт (если он
есть в ответе) подставляются после нажатия «Проверить данные». Сферу берём из
названия основного ОКВЭД, а если доступен только код, используем подсказки для
распространённых отраслей. Сферу и сайт можно исправить вручную. Юридический
адрес предлагается отдельно.

Первый черновик оффера использует подтверждённую сферу и название бизнеса.
Скидку, промокод и срок действия задаёт клиент. Сайт сохраняется в заявке.

Для локального запуска положите `DADATA_API_KEY` и `DADATA_SECRET_KEY` в
игнорируемый Git файл `.env.autocomplete` с правами `600`. Для Docker задайте
их в серверном `.env`, для systemd — в `/etc/ads-autocomplete.env` с правами `600`.
Метод [DaData «Организация по ИНН»](https://dadata.ru/api/find-party/) использует
API-ключ. Secret остаётся в окружении Autocomplete и этому методу не передаётся.
Старый маршрут `/api/business/lookup` поддерживается как алиас.

```
api/openapi.yaml   контракт: источник правды для интерфейса и бэкенда
server/            тестовый бэкенд: Hono + node:sqlite, ~630 строк
  index.ts         маршруты по контракту
  domain.ts        справочники и расчёты: прогноз, статистика, модерация, выплаты
  db.ts            таблицы и начальные данные кофейни «Зерно»
  flow.test.ts     сквозной тест
src/api.ts         клиент: openapi-fetch + TanStack Query, типы из контракта
src/api.gen.ts     сгенерированные типы, руками не править
src/screens/       экраны: лендинг, вход, сценарий запуска, сборка, кабинет, витрина «лучшее рядом» для абонента
src/creative.tsx   креатив карточки витрины: код рисует текст, картинка из public/img/near
```

Каждый посетитель получает свою копию демо-компании, она привязана к cookie `demo`. Показы не мешают друг другу. «Экраны прототипа» → «сбросить демо» начинает заново. Подтверждение руководителем открывается по ссылке `/#/approve/<token>` без cookie, поэтому работает и с телефона. Заброшенные копии старше 30 дней удаляются.

## Подключить настоящий бэкенд

1. Реализовать `api/openapi.yaml`. Ответы тестового сервера — образец, `server/flow.test.ts` — сценарий приёмки: замените в нём `app.request` на `fetch` к своему адресу.
2. Собрать интерфейс с адресом API: `VITE_API_URL=https://api.example.ru npm run build`. Запросы идут с `credentials: 'include'`, поэтому для другого домена нужен CORS с разрешёнными cookie.
3. Удалить `server/`.

Демо-особенности контракта, которых не будет в бою, описаны в начале `openapi.yaml`: копия компании по cookie, `Session.clock` для перемотки времени, мгновенные оплаты и ЭДО.

## Стек

Vite 8, React 19, TypeScript 7, React Router 8, TanStack Query 5, openapi-fetch, Hono 4, Motion 14 (анимации), Recharts 3 (графики), Lucide (иконки). `openapi-typescript` запускается через `npx` вместе с TypeScript 5: генератору нужен JS-API компилятора, которого нет в TypeScript 7. В `.npmrc` включён `legacy-peer-deps`: npm 10 падает на необязательных пиковых зависимостях Vite 8.

Фото лежат в `public/img/`, промты для генерации — в «Промпты для фото (ChatGPT).md».
