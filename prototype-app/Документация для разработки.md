## 1. Что это и как устроено

Кликабельный прототип кабинета, в котором малый и средний бизнес сам запускает рекламу в приложении билайна. Путь партнёра: лендинг → вход по бизнес-ID → согласия → охват и прогноз → сборка кампании → оплата или оферта → проверка и запуск → статистика, баланс, документы.

Подход API first: интерфейс не хранит данных и ничего не считает сам. Всё, что он показывает и меняет, идёт через запросы из контракта. Тестовый сервер реализует контракт поверх SQLite, чтобы прототип работал по-настоящему. Бэкенд пишется по тому же контракту, после чего тестовый сервер удаляется.

```
браузер ──► src/api.ts ──► /api/* ──► server/index.ts ──► server/db.ts ──► SQLite
           типы из контракта          маршруты           хранение
                                     server/domain.ts — справочники и расчёты
```

| Путь | Что внутри |
|---|---|
| `api/openapi.yaml` | Контракт OpenAPI 3.1: 25 операций, схемы, ошибки |
| `src/api.gen.ts` | Типы, сгенерированные из контракта. Руками не править: `npm run api:types` |
| `src/api.ts` | Клиент: openapi-fetch и TanStack Query, хуки чтения, правка с задержкой |
| `src/screens/` | Экраны: лендинг, вход, сценарий запуска, сборка, кабинет |
| `server/index.ts` | Маршруты тестового сервера (Hono) |
| `server/domain.ts` | Справочники и расчёты: прогноз, модерация, шаги запуска, статистика, выплаты |
| `server/db.ts` | Таблицы SQLite и начальные данные кофейни «Зерно» |
| `server/flow.test.ts` | Сквозной тест, он же сценарий приёмки бэкенда |
| `server/ads-proto.service` | systemd-служба API на стенде |

**Стек.** Vite 8, React 19, TypeScript 7, React Router 8, TanStack Query 5, openapi-fetch, Hono 4, SQLite из Node (`node:sqlite`), Motion 14, Recharts 3, Lucide.

**Как интерфейс ходит в API.**
- Чтение — через Suspense-хуки (`useCampaign`, `useCompany` и т. д.): пока данных нет, экран ждёт на общей границе загрузки.
- После любого изменения клиент перечитывает все запросы на экране (`queryClient.invalidateQueries()`), а ошибку показывает тостом с `message` из ответа.
- Ползунки и поля ввода шлют PATCH через 400 мс после последнего изменения (`useLater`).
- Пока кампания в статусе `moderation`, клиент опрашивает её раз в 700 мс: шаги запуска двигает сервер.
- Все запросы идут с `credentials: 'include'`, адрес задаёт `VITE_API_URL` (по умолчанию `/api`).

## 2. Запуск

Нужен Node 22.18 или новее: в нём есть встроенная SQLite и запуск TypeScript без сборки. Версия записана в `.nvmrc`.

```bash
npm install
npm run dev
```

API поднимается на http://127.0.0.1:8787/api, интерфейс на http://127.0.0.1:5173. Vite проксирует `/api` на сервер.

| Команда | Что делает |
|---|---|
| `npm run dev` | API и интерфейс вместе, с перезапуском при правках |
| `npm run server` | только API. Переменные: `API_PORT` (8787), `DB_PATH` (`server/demo.sqlite`, `:memory:` — в памяти) |
| `npm test` | сквозная проверка API |
| `npm run api:types` | пересобрать `src/api.gen.ts` из контракта; запускать после каждой правки `openapi.yaml` |
| `npm run build` | проверка типов и сборка интерфейса в `dist/` |

`openapi-typescript` запускается через `npx` вместе с TypeScript 5: генератору нужен JS-API компилятора, которого нет в TypeScript 7.

## 3. Предметная модель

### Компания

Юрлицо партнёра: реквизиты, сегмент (`small`, `medium`, `large`), согласия, настройки уведомлений, оператор ЭДО, автопополнение, дата принятия оферты. У компании есть:
- **точки продаж** — адреса с координатами на карте охвата и флагом «в рекламе». Хотя бы одна точка всегда активна;
- **люди** — владелец-подписант, сотрудник-маркетолог, приглашённые бухгалтеры.

Сегмент задаёт режим сборки новой кампании: малый бизнес — автопилот, средний — ручная настройка, крупный — медиаплан.

### Сессия

Кто вошёл и как: способ входа (`gos` — Госуслуги, `sber` — СберБизнес ID, `alfa` — Альфа ID, `inn` — без входа, по открытым данным), роль (`boss` — руководитель, `staff` — сотрудник) и демо-часы `clock` (см. раздел 9). Принять оферту и оплатить можно только после входа по бизнес-ID.

### Кампания

Главная сущность. Партнёр задаёт:

| Поле | Что это |
|---|---|
| `type` | тип оффера (таблица ниже) |
| `mode` | режим сборки: `auto` автопилот, `manual` вручную, `plan` медиаплан, `special` спецпроект |
| `goal` | цель автопилота: `near` соседи в точку, `rivals` клиенты конкурентов, `showcase` Витрина выгод |
| `adText`, `img` | текст объявления (до 90 символов) и вариант картинки |
| `terms` | условия оффера: поля зависят от типа, плюс `via` — способ подтверждения результата |
| `audience` | для ручного режима: сигнал → блок `any` (любой из), `and` (и), `not` (кроме) |
| `places` | места показа: Витрина выгод, главная, «Платёж прошёл», экран остатков, магазин, пуш, меню ТВ |
| `budget` | бюджет в месяц, от 3 000 ₽ |
| `amount` | сколько внести сейчас; `null` — равно бюджету |
| `payMethod` | `sbp`, `card`, `invoice` (счёт-оферта), `post` (постоплата, только крупный бизнес) |

Сервер добавляет вычисляемые поля: `name`, `deal` (строка условий и кнопка объявления), `forecast`, `moderation`, `launchStep`, `launchedAt`, `totals`.

### Типы офферов

Путь подключения одинаковый для всех типов. Отличаются условия, расчёт и то, кто кому платит.

| `type` | Название | Кто платит | Условия (`terms`) | Подтверждение результата (`terms.via`) |
|---|---|---|---|---|
| `click` | реклама с оплатой за переход (основной) | партнёр, с баланса за клик | нет | не нужно |
| `coupon` | купон со скидкой | клиент платит билайну; партнёру выплата за погашенный купон минус 20 % | `what`, `price`, `old` | код в кабинете, приложение кассира, коннектор к кассе |
| `lead` | оплата за заявку | партнёр, с баланса фикс за подтверждённую заявку | `what`, `price` | почта, Битрикс24, amoCRM, API |
| `promo` | промокод на покупку | партнёр, с баланса процент с оплаченной покупки | `code`, `off`, `fee`, `check` | файл раз в неделю, постбэк, коннектор 1С |
| `sub` | подписка на сервис | клиент платит со счёта телефона; партнёру доля каждого платежа минус 30 % | `what`, `price`, `trial` | коды доступа, API |

Флаг `share` в справочнике: `true` у купона и подписки. Такой кампании не нужны бюджет и оплата, вместо баланса у партнёра появляются выплаты. Значения `terms` — строки, числовые поля помечены в справочнике `num: true` и должны быть больше нуля.

### Деньги

- **Баланс** пополняется оплатой кампании (СБП, карта, счёт, постоплата) и отдельными пополнениями. Первая оплаченная кампания даёт бонус 3 000 ₽. С баланса списываются клики, заявки и покупки кампаний с `share: false`.
- **Выплаты** копятся по кампаниям с `share: true` и уходят на расчётный счёт 1-го числа. Комиссия билайна удерживается из выплаты.
- **Документы**: оферта, счета-оферты, акты, счета-фактуры, отчёт агента (если есть купоны или подписки). Закрывающие документы приходят через ЭДО.

## 4. Жизненный цикл кампании

```
                   сотрудник                    руководитель по ссылке
  draft ──submit──► approval ──confirm──┬────────────────────────────────┐
    │                         (СБП или карта: approved, затем pay) ──────┤
    │ руководитель                                                       ▼
    └──submit──┬── счёт-оферта ──► invoice ──invoice-paid──► moderation ──► live ◄──► paused
               └── СБП, карта, постоплата, купон, подписка ─────► │          (PATCH paused)
                                                                  ▼
                                                    rejected (текст не прошёл проверку)
                                                    PATCH adText ──► снова moderation
```

| Статус | Что значит | Что можно делать |
|---|---|---|
| `draft` | черновик | менять всё, отправлять |
| `approval` | сотрудник отправил руководителю | руководитель подтверждает по ссылке; сотрудник может отправить повторно |
| `invoice` | выставлен счёт, ждём денег | отметить оплату (`invoice-paid`) |
| `moderation` | проверка, маркировка, подключение | ждать: `launchStep` растёт от 0 до 3 |
| `rejected` | в тексте стоп-слово | исправить `adText`: проверка начнётся заново |
| `live` | показывается | пауза, советы, статистика |
| `paused` | на паузе, деньги не списываются | возобновить |

**Шаги запуска** (`launchStep`): 0 — ИИ-проверка текста и картинки, 1 — маркировка (erid, передача в ОРД), 2 — подключение способа подтверждения (у `click` его нет, интерфейс этот шаг не показывает, но сервер проходит его так же), 3 — показы. На тестовом сервере шаги двигаются по времени от отправки: 1,6 с, 2,8 с и 4 с.

`rejected` и `live` на тестовом сервере не хранятся, а вычисляются при каждом чтении из сохранённого статуса `moderation`: есть стоп-слово — `rejected`, прошли 4 с — `live`.

**Роли при отправке** (`POST /campaigns/{id}/submit`):
- **Руководитель** передаёт `acceptOffer: true` и сразу оплачивает. Деньги на баланс зачисляются в момент отправки, кроме счёта: по нему после `invoice-paid`.
- **Сотрудник** получает статус `approval` и `approvalToken`. Ссылка `/#/approve/<token>` открывается без входа, например на телефоне руководителя. Руководитель подтверждает через бизнес-ID (`confirm`). Если выбраны СБП или карта, следом идёт оплата (`pay`). Иначе дальше как при отправке руководителем: счёт-оферта переводит кампанию в `invoice`, постоплата, купон и подписка — сразу в проверку.

## 5. Справочник API

Базовый адрес — `/api`. Все тела запросов и ответов — JSON. Компанию определяет cookie `demo` (раздел 9): её ставит первый же запрос, кроме `/catalog` и `/approvals/*`, которые работают без неё.

### Справочники

| Метод и путь | Что делает | Ответ |
|---|---|---|
| `GET /catalog` | типы офферов, цели, сигналы, места показа, способы входа, сегменты, способы оплаты, картинки, размер бонуса | `Catalog` |

### Сессия

| Метод и путь | Тело | Что делает | Ответ |
|---|---|---|---|
| `GET /session` | — | кто вошёл | `Session` |
| `PATCH /session` | `{ role?, clock? }` | демо: сменить роль или время с запуска | `Session` |
| `POST /session/login` | `{ provider }` | вход по бизнес-ID или по ИНН; 400 на неизвестный способ | `Session` |
| `POST /session/reset` | — | демо: удалить копию компании и выдать новую | `Session` |

### Компания

| Метод и путь | Тело | Что делает | Ответ, ошибки |
|---|---|---|---|
| `GET /company` | — | реквизиты, точки, люди | `Company` |
| `PATCH /company` | `{ segment?, consents?, notify?, autoTopup?, edo? }` | изменить настройки; `edo` — имя оператора, подключает ЭДО | `Company` |
| `POST /company/points` | `{ addr }` | добавить точку | `Company`; 400 — адрес короче 5 символов |
| `PATCH /company/points/{pointId}` | `{ active }` | включить или исключить точку | `Company`; 404; 409 — последнюю активную не выключить |
| `POST /company/members` | `{ email }` | пригласить бухгалтера | `Company`; 400 — неверная почта |

### Кампании

| Метод и путь | Тело | Что делает | Ответ, ошибки |
|---|---|---|---|
| `GET /campaigns` | — | все кампании компании, новые сверху | `Campaign[]` |
| `POST /campaigns` | `{ type }` | черновик выбранного типа с настройками по умолчанию | `Campaign`; 400 — неизвестный тип |
| `GET /campaigns/{id}` | — | кампания с прогнозом, проверкой текста и шагом запуска | `Campaign`; 404 |
| `PATCH /campaigns/{id}` | `CampaignPatch` | изменить настройки (правила ниже) | `Campaign`; 404 |
| `POST /campaigns/{id}/submit` | `{ acceptOffer? }` | отправить на запуск (раздел 4) | `Campaign`; 400, 404, 409 |
| `POST /campaigns/{id}/invoice-paid` | — | демо: оплата по счёту поступила | `Campaign`; 409 — счёт не ждёт оплаты |
| `GET /campaigns/{id}/stats` | — | статистика на момент `Session.clock` | `Stats`; 409 — до запуска |
| `POST /campaigns/{id}/tips/{tipId}` | — | применить совет из статистики (`morning`, `rest`) | `Campaign`; 404 |
| `POST /special-requests` | `{ kind, task, budget }` | заявка на спецпроект менеджеру | `{ id }`; 400 — задача короче 10 символов |

**Правила `PATCH /campaigns/{id}`:**
- `type` — смена типа сбрасывает `terms` на значения по умолчанию и текст объявления;
- `goal` и любые `terms`, кроме одного `via`, сбрасывают текст объявления: текст по умолчанию собирается из цели или условий;
- `adText: null` — вернуть текст по умолчанию. Новый текст у кампании в проверке запускает проверку заново;
- `budget` меньше 3 000 ₽ поднимается до 3 000;
- `paused` действует только на запущенной кампании;
- `audience` и `places` заменяются целиком, `terms` дополняются.

**Проверки `submit`** (в этом порядке):

| Код | Когда |
|---|---|
| 404 | кампании нет |
| 409 | статус не `draft` и не `approval` |
| 400 | ручной режим без сигналов в «любой из» или «и» |
| 400 | числовое поле условий пустое или ноль |
| 400 | `amount` меньше 3 000 ₽ у кампании с бюджетом |
| 409 | вход без бизнес-ID (`provider` пуст или `inn`) |
| 400 | руководитель без `acceptOffer: true` |

### Подтверждение руководителем

Работает по токену, без cookie.

| Метод и путь | Тело | Что делает | Ответ, ошибки |
|---|---|---|---|

| `POST /approvals/{token}/pay` | — | оплатить и запустить | `Approval`; 409 — оферта ещё не принята |

### Деньги и документы

| Метод и путь | Тело | Что делает | Ответ, ошибки |
|---|---|---|---|
| `GET /balance` | — | баланс, на сколько дней хватит, выплаты, операции | `Balance` |
| `POST /balance/topups` | `{ amount }` | пополнить по СБП (в демо сразу) | `Balance`; 400 — меньше 1 000 ₽ |
| `GET /documents` | — | оферта, счета, акты, отчёт агента | `Document[]` |

## 6. Схемы данных и примеры

Полные схемы с описаниями полей — в `components/schemas` контракта. Ниже — реальные ответы тестового сервера.

**Деньги** в ответах — рубли. Цены и суммы к оплате — целые числа, поля прогноза (`forecast`) — дробные, интерфейс округляет их сам. **Идентификаторы** — целые числа, кроме токена подтверждения. **Даты** — ISO 8601.

### Campaign

Купон в статусе черновика, вход через СберБизнес ID:

```json
{
  "id": 2,
  "type": "coupon",
  "status": "draft",
  "name": "купон: капучино и круассан",
  "mode": "auto",
  "goal": "near",
  "adText": "Капучино и круассан за 350 ₽ вместо 700 ₽. Купон в приложении билайна",
  "img": 0,
  "terms": { "what": "капучино и круассан", "price": "350", "old": "700", "via": "код в кабинете" },
  "audience": { "live": "any", "work": "any", "rival": "and" },
  "places": { "showcase": true, "main": true, "paid": true, "rest": false, "shop": false, "push": false, "tv": false },
  "budget": 10000,
  "amount": null,
  "payMethod": "sbp",
  "tips": [],
  "approvalToken": null,
  "createdAt": "2026-10-24T10:04:33.260Z",
  "launchedAt": null,
  "launchStep": 0,
  "deal": { "line": "350 ₽ вместо 700 ₽ · комиссия 20 %", "offer": "капучино и круассан за 350 ₽", "cta": "купить за 350 ₽" },
  "forecast": {
    "reach": 12400, "cpc": 9, "clicks": 1111.11, "visits": 288.89, "guest": 34.62,
    "results": 372, "per": 280, "money": 104160,
    "amount": 0, "payClicks": 0, "payVisits": 0, "payResults": 0, "audienceEmpty": false
  },
  "moderation": null,
  "totals": null
}
```

`forecast` — прогноз на месяц:

| Поле | Смысл |
|---|---|
| `reach` | подходящих людей рядом с активными точками |
| `clicks`, `cpc`, `visits`, `guest` | клики, цена клика, визиты в точку, цена одного гостя |
| `results` | главный результат типа: визиты, погашенные купоны, заявки, покупки, подписки |
| `per` | цена результата; для купона и подписки — выплата партнёру за единицу |
| `money` | потратите за месяц, а для купона и подписки — получите |
| `amount`, `payClicks`, `payVisits`, `payResults` | к оплате сейчас и на что этого хватит |
| `audienceEmpty` | в ручном режиме нет ни одного сигнала |

`moderation` — `null` или `{ word, why, fix }`: найденное слово, норма закона «О рекламе», предлагаемая замена. `totals` — `{ clicks, results }` для списка кампаний после запуска.

### Stats

Тот же купон через две недели (`clock: d14`), массивы укорочены:

```json
{
  "clock": "d14",
  "reach": 9920, "reachTotal": 12400, "impressions": 18648,
  "clicks": 333, "ctr": 1.2, "results": 186, "returning": 0,
  "spent": 0, "payout": 52080, "per": 280, "cpc": 9,
  "hourly": [{ "label": "08:00", "value": 2 }],
  "daily": [{ "label": "1 ноя", "value": 2 }],
  "breakdownBy": "places",
  "breakdown": [{ "label": "Витрина выгод", "clicks": 186, "ctr": 3.1, "results": 104, "per": 280 }],
  "tips": [{ "id": "morning", "title": "показывать чаще утром", "detail": "ещё ≈ 28 купонов", "doneTitle": "утром показываем чаще", "applied": false }]

```

В первые 48 часов `daily`, `breakdown` и `tips` пустые: экран показывает живые счётчики и клики по часам. `breakdownBy: signals` — разбивка по сигналам для ручного режима.

### Balance

```json
{
  "balance": 0,
  "daysLeft": null,
  "low": false,
  "autoTopup": false,
  "operations": [],
  "payout": { "due": 52080, "date": "1 декабря", "gross": 65100, "fee": 13020, "count": 186, "unit": "погашенные купоны" }
}
```

`daysLeft` — `null`, если нет запущенных кампаний с бюджетом. `low: true` — денег меньше чем на 3 дня. `payout` — `null`, если нет купонов и подписок. Операции — `{ date, title, amount }`, списания с минусом.

### Остальное

- **Session** — `{ "provider": "sber", "role": "boss", "clock": "h48" }`.
- **Company** — реквизиты (`name`, `brand`, `inn`, `kpp`, `ogrn`, `bank`, `acc`, `site`, `phone`, `signer`, `signerShort`, `signerRole`, `employee`), `segment`, `consents { company, signer, profile }`, `notify { sms, mail, tg }`, `edo`, `autoTopup`, `offerAcceptedAt`, `points[] { id, addr, x, y, active }`, `members[] { id, name, email, role, title }`.
- **Approval** — `{ company, signerShort, employee, campaign, approved, needsPay }`.
- **Document** — `{ id, title, date, status }`.
- **Catalog** — `offerTypes`, `goals`, `signals` (группы с сигналами, `v`: `hot`, `week`, `wide`, `off` — не продаётся), `places`, `providers`, `segments`, `payMethods` (`largeOnly` — только крупному бизнесу), `images`, `bonus`. Тексты типов офферов (`t`, `d`, `cta`, `unit`, `per`, `wait` и др.) интерфейс выводит как есть, поэтому их правка не требует выкладки интерфейса.

## 7. Расчёты тестового сервера

Все цифры — иллюстративные заглушки на примере кофейни с двумя точками. Они нужны, чтобы интерфейс вёл себя правдоподобно, и описывают смысл полей, а не боевую модель. В бою прогноз даёт аукцион, статистику — хранилище событий. Код — `server/domain.ts`.

| Что | Как считает заглушка |
|---|---|
| охват | автопилот: охват цели × (активные точки / 2). Вручную: сумма охватов сигналов «любой из» × 0,8, каждое «и» сужает, каждое «кроме» минус 8 % |
| клики, визиты | `budget / cpc`, `clicks × conv`; конверсия из цели или 0,24 вручную |
| переход | `results` = визиты, `per` = цена гостя |
| заявка | `per` = цена заявки, `results = budget / per` |
| промокод | `per` = средний чек × комиссия %, `results = budget / per` |
| купон | `per` = цена × 0,8, `results` = охват × 3 %, `money = results × per` |
| подписка | `per` = цена × 0,7, `results` = охват × 0,8 %, `money = results × per` |
| списано с баланса | 48 часов: 380 ₽; 2 недели: меньшее из `budget × 0,64` и `amount + 3 000` |
| выплата | `count` = `results` × 2 % (48 часов) или 50 % (2 недели), `due = count × per`, `gross = due / (1 − комиссия)` |
| модерация | регулярные выражения на «лучший…» и «самый…» без подтверждения (п. 1 ч. 3 ст. 5 закона «О рекламе») |

## 8. Ошибки

Любая ошибка — JSON `{ "message": "текст для человека" }`. Интерфейс показывает `message` как есть, поэтому текст должен быть понятен партнёру.

| Код | Когда |
|---|---|
| 400 | неверные данные: короткий адрес, неверная почта, пустые условия, сумма меньше минимума, оферта не принята |
| 404 | нет кампании, точки, ссылки подтверждения или такого запроса |
| 409 | действие не подходит к состоянию: кампания уже отправлена, статистика до запуска, последняя точка, вход без бизнес-ID |
| 500 | `{ "message": "ошибка сервера" }`, подробности — в логе сервера |

## 9. Демо-упрощения и что нужно в бою

| В прототипе | В бою |
|---|---|
| Компанию определяет cookie `demo` (httpOnly, SameSite=Lax, год). Каждый посетитель получает свою копию «Зерна», копии старше 30 дней удаляются | вход через ЕСИА, СберБизнес ID, Альфа ID для бизнеса; компания и роль — из токена |
| `POST /session/login` верит переданному `provider` | OAuth-поток провайдера, реквизиты и точки — из его ответа, DaData и Яндекс Карт |
| Роль меняется переключателем (`PATCH /session { role }`) | роль из прав пользователя в компании |
| `Session.clock` перематывает время: первые 48 часов или 2 недели | реальное время, статистика за период |
| Оплата СБП и картой проходит в момент `submit` | платёжный шлюз, подтверждение вебхуком, идемпотентность оплаты |
| `invoice-paid` отмечает оплату счёта вручную | выписка банка или вебхук |
| ЭДО подключается одной кнопкой | приглашение через оператора ЭДО, статусы документов |
| Шаги запуска двигаются по таймеру | очередь модерации, ОРД (erid), проверка подключения способа подтверждения |
| Модерация — два регулярных выражения | ИИ-проверка и ручная очередь |
| Прогноз и статистика — формулы из раздела 7 | аукцион и хранилище событий |
| Кампании и реквизиты хранятся JSON-ом в SQLite | нормальная схема; модель данных — в контракте |
| Токен подтверждения — 8 символов без срока жизни | длинный одноразовый токен со сроком действия |

**Чего в контракте пока нет и понадобится:**
- пагинация и фильтры в `GET /campaigns`, `GET /documents` и операциях баланса;
- суммы в копейках, чтобы не терять точность;
- статистика за произвольный период (`from`, `to`) вместо `clock`;
- загрузка картинки и файла базы клиентов, подтверждение результатов партнёром (заявки, погашения купонов, заказы по промокоду);
- права ролей: что может сотрудник, что бухгалтер;
- удаление и архив кампаний, история изменений;
- вебхуки для партнёра: новая заявка, погашенный купон, мало денег на балансе.

## 10. Как подключить настоящий бэкенд

1. Реализовать `api/openapi.yaml`. Ответы тестового сервера — образец: поднимите его (`npm run server`) и сравнивайте.
2. Прогнать приёмку: в `server/flow.test.ts` заменить `app.request` на `fetch` к своему адресу и запустить `npm test`. Тест проходит путь перехода от входа до баланса, путь купона с подтверждением руководителем и выплатами, ответы на ошибки.
3. Собрать интерфейс с адресом API: `VITE_API_URL=https://api.example.ru npm run build`. Запросы идут с cookie, поэтому для другого домена нужен CORS с `Access-Control-Allow-Credentials: true` и точным `Origin`.
4. Удалить `server/`, служебные команды из `package.json` и зависимости `hono`, `@hono/node-server`.

Меняете контракт — сначала правьте `openapi.yaml`, потом `npm run api:types`. TypeScript покажет все места в интерфейсе, которые нужно поправить.

## 11. Выкладка стенда

Стенд — https://ads.napovtor.ru, закрыт от поисковиков (robots.txt, meta robots, заголовок `X-Robots-Tag`).

```bash
sh deploy.sh
```

Скрипт прогоняет тест, собирает интерфейс и копирует его в `/var/www/ads.napovtor.ru`, дизайн-систему — в `/design-system/`, сервер — в `/opt/ads-proto`. Затем ставит зависимости и перезапускает службу `ads-proto`.

| Что | Где |
|---|---|
| служба API | systemd `ads-proto`, порт 8787, пользователь `www-data` |
| база | `/var/lib/ads-proto/demo.sqlite` |
| Node | 22.23.3 отдельно в `/opt/node22`. Системный Node 20 не трогать: на нём работают приложения под pm2 |
| nginx | `/etc/nginx/sites-available/ads-napovtor`, `location /api/` → `127.0.0.1:8787` |
| логи | `journalctl -u ads-proto` |
