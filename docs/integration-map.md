# Карта интеграций для команд билайна

30.10.2026. Для владельцев систем билайна, с которыми рекламной платформе предстоит связаться. По каждой системе: что платформа будет делать, что для этого нужно от команды, как проверим и сколько это займёт на нашей стороне. Технический справочник портов — [integrations.md](integrations.md).

## 1. Как устроено подключение

Платформа уже работает автономно: за каждой системой стоит заглушка, которая ведёт себя как настоящая. Подключение системы — это адаптер на нашей стороне, переводящий наш запрос на её API. Ядро платформы при этом не меняется. Включается адаптер одной настройкой и так же выключается, если что-то пошло не так.

Общие правила для всех систем:

| Тема | Как у нас |
|---|---|
| повторы | каждая операция несёт ключ идемпотентности; мы можем повторить запрос, и система должна узнать повтор |
| недоступность | изменения уходят через очередь с повторами (10 с, 40 с, 2,5 мин… до часа, 8 попыток); упавшие видны сотрудникам и повторяются кнопкой |
| события от системы | `POST /api/hooks/<система>/<событие>`, подпись HMAC-SHA256 тела в `X-Signature`, уникальный `X-Event-Id`; повтор события безопасен |
| журнал | каждый вызов и событие — в журнале интеграций бэкофиса, без секретов и персональных данных |
| персональные данные абонентов | номера телефонов не храним и не принимаем; ключ абонента — MED-ID |
| деньги | целые копейки |

## 2. Что нужно от каждой команды

Для каждой системы одинаковый стартовый набор:

1. Документация API и контакт технического специалиста.
2. Тестовый контур и учётные данные к нему.
3. Секрет подписи событий (если система шлёт события нам) и адреса для белых списков.
4. Договорённость о формате ID: что система считает ключом повтора.

Срок на нашей стороне — после того, как всё это получено. Оценка включает адаптер, тесты на тестовом контуре и включение на стенде.

## 3. Первая волна — без неё нельзя принимать реальные деньги

| Система | Что делает платформа | Особое, что нужно от команды | Оценка |
|---|---|---|---|
| **Вход партнёров**: Госуслуги (ЕСИА), СберБизнес ID, Альфа ID для бизнеса | вход руководителя, реквизиты компании, подтверждение полномочий подписанта | зарегистрированные клиенты OAuth/OIDC у каждого провайдера, адреса возврата, перечень атрибутов о полномочиях в организации | 2–3 дня на провайдера |
| **SSO сотрудников** билайна | вход в бэкофис, роли moderator, manager, finance, admin | группы каталога для четырёх ролей, OIDC-клиент | 1 день |
| **Реестр юрлиц**: DaData или Контур.Фокус | проверка компании по ИНН: статус, реквизиты, руководитель, риск | ключ API с лимитом под число регистраций | 1 день |
| **Эквайринг**: СБП и карты | пополнение баланса, подтверждение оплаты событием, возврат | мерчант, тестовые карты, события об оплате с подписью | 3–4 дня |
| **Выписка** расчётного счёта | зачисление оплат по счетам-офертам: номер счёта в назначении, ИНН плательщика, сумма | доступ к выписке (API банка или выгрузка), формат назначения платежа | 2 дня |
| **Учётная система**: SAP или 1С | контрагенты, выручка по актам, заявки на выплаты партнёрам | справочник контрагентов, формат проводки выручки, процесс выплаты | 4–5 дней |
| **ЭДО**: оператор билайна | приглашение партнёра, отправка актов и счетов-фактур, статусы подписи | оператор, ящик билайна, событие о статусе документа | 3 дня |
| **Подпись**: ПЭП по SMS или КЭП | акцепт оферты, подтверждение руководителем | решение юристов: ПЭП или КЭП; провайдер | 2 дня |
| **ОРД** | организация, договор, креатив → erid; статистика за месяц | договор с ОРД, тестовый контур, кто подаёт данные в ЕРИР | 3 дня |
| **Реестр согласий** абонентов | можно ли показывать рекламу и слать пуш конкретному MED-ID | API проверки согласия, время ответа до 20 мс или выгрузка | 2 дня |
| **Поверхности**: «Мой билайн», beeline.ru, Магазин | запрос рекламы на место показа, маяк показа, клик | ключ поверхности, где в приложении живёт место показа, передача MED-ID и координат | 1–2 дня на поверхность (у нас), встраивание — у команды поверхности |
| **SMS и почта** | уведомления партнёру: запуск, отказ, заявка, баланс, выплата | SMS-шлюз билайна, почтовый сервис, отправитель | 1 день |
| **Модель** (Claude или ИИ билайна) | проверка текста и картинки объявления | доступ к модели в контуре билайна или разрешение на внешнюю | 1–2 дня |
| **Хранилище файлов**: S3 облака билайна | картинки креативов, документы | бакет, ключи, CDN для картинок | 1 день |

**Итого первая волна** — около 30 рабочих дней на нашей стороне, если доступы приходят вовремя. Системы независимы, их можно подключать параллельно двумя людьми — тогда 3–4 недели.

## 4. Вторая волна — рост охвата

| Система | Что даёт | Оценка |
|---|---|---|
| **DMP / Big Data**, MED-ID | сигналы абонента в момент показа (переезд, зарплата, маршрут), точный охват в прогнозе; ответ до 20 мс | 4–5 дней |
| **Биллинг абонентов** | покупка купона и подписки со счёта телефона, бонусы гигабайтами, продления подписок событиями | 4 дня |
| **CVM**: пуши, входящие | доставка оффера по триггеру с частотой по всем каналам билайна | 3 дня |
| **Билайн Adtech** | антифрод кликов; затем — внешний инвентарь и, по договорённости, выбор рекламы | 3 дня на антифрод |
| **CRM корпоративных клиентов** | «уже клиент билайна», персональный менеджер, заявки на спецпроекты | 2 дня |
| **CRM партнёров**: Битрикс24, amoCRM | заявки уходят прямо в CRM партнёра | 2 дня на систему |
| **Кассы партнёров** | погашение купона на кассе событием | 2 дня |
| **Service desk** | обращения и спецпроекты в очереди менеджеров | 1 день |
| **Мониторинг** | метрики и алерты в системе билайна | 1 день |

## 5. Третья волна — масштаб

| Система | Что даёт |
|---|---|
| **Сигналы партнёров данных**: X5, Альфа-Банк, страховщики | триггеры с подтверждённой покупкой и закрытым циклом (тир T4) через контур билайна |
| **BI**: DataLens, хранилище | отчёты руководству из агрегатов платформы |
| **Внешний инвентарь** (OpenRTB через Adtech) | показ рекламы партнёров вне поверхностей билайна |

## 6. Как проверяем каждое подключение

1. Сценарии, которые сейчас проходят на заглушке, повторяются на тестовом контуре системы: обычный ответ, отказ, повтор, недоступность.
2. Сквозной сценарий приёмки (`server/e2e.test.ts`: регистрация → кампания → оплата → модерация → erid → показ → клик → списание → статистика → акт) проходит с включённым адаптером.
3. На стенде адаптер включается, журнал интеграций бэкофиса неделю смотрится на ошибки, только потом — бой.

## 7. Вопросы, которые решаются не в коде

| Вопрос | Кому | От чего зависит |
|---|---|---|
| какой ОРД и кто подаёт данные в ЕРИР | юристы, маркетинг | маркировка, отчётность |
| ПЭП или КЭП для акцепта оферты | юристы | вход и подписание |
| оферта, агентская схема для купонов и подписок | юристы, финансы | документы, выплаты |
| строим поверх Билайн Adtech или рядом | руководство Adtech | выбор рекламы, антифрод, внешний инвентарь |
| где живёт платформа: облако билайна, требования ИБ к контуру с ПДн | ИБ, инфраструктура | выкладка в бой |
| кто владеет CVM и как делим частоту между каналами | CVM | пуши и входящие |
| ставка НДС и реквизиты продавца в документах | финансы | акты и счета-фактуры |
