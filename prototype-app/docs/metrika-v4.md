# Воронка V4 в Яндекс Метрике

Разметка покрывает лендинг, ввод данных компании, создание оффера, выбор клиентов и сохранение настроек. Финальная конверсия означает успешное сохранение настроек в текущем прототипе. Она не означает регистрацию, отправку заявки, оплату или запуск рекламы.

Номер счётчика пока не задан. Код готов к подключению; запросов в Яндекс без номера нет. Цели и отчёты в аккаунте Метрики ещё не созданы.

## Подключение

В `prototype-app/.env.local` для Vite или `.env` для Docker указать публичную настройку `VITE_METRIKA_ID`. После изменения пересобрать web. В Docker ID передаётся как build argument через Compose; простой перезапуск готового контейнера его не заменяет. Секретные ключи не нужны и в клиент не передаются.

Для локальной проверки:

```sh
VITE_METRIKA_DEBUG=true npm run dev
```

Команда выполняется из `prototype-app` с Node 22.18+. Диагностика выводит JSON в консоль с префиксом `[metrika]`. Она работает без номера счётчика и показывает тот же поток просмотров и событий. На localhost и 127.0.0.1 отправка в Яндекс отключена даже при заданном номере. На публичном домене счётчик активен только при корректном положительном целочисленном ID. Диагностика по умолчанию выключена.

Инициализация использует `defer: true`, ручные `hit` для SPA и `reachGoal` для событий. Автоматическое отслеживание hash, внешних ссылок, карта кликов и Вебвизор выключены. Один переход создаёт один просмотр; повторный React effect не дублирует его. Возврат на прежний шаг считается новым просмотром. Непроверенный URL успеха не создаёт просмотр успеха: его отправляет только реально открытый, допущенный проверкой экран.

## Основная воронка

В отчёте «Воронки» построить последовательность:

| Шаг | Идентификатор | Что произошло |
|---|---|---|
| Лендинг | `v4_landing_view` | Открыт маршрут V4 |
| Начало оформления | `v4_cta_click` | Нажата одна из кнопок запуска |
| Контактные данные | `v4_identify_complete` | Корректные ИНН и телефон, переход к данным компании |
| Информация о компании | `v4_business_complete` | Название, сфера и адреса прошли проверку |
| Оффер принят | `v4_offer_complete` | Корректный оффер, пользователь продолжил к клиентам |
| Настройка завершена | `v4_setup_complete` | Финальное сохранение успешно |

Для составной цели из пяти шагов использовать цепочку от `v4_cta_click` до `v4_setup_complete`, без первого просмотра лендинга. Детальные просмотры и промежуточные действия использовать для поиска причин потерь. У прямых ссылок и восстановленных черновиков могут отсутствовать ранние действия: анализировать их отдельным сегментом, а не считать ошибкой последовательности.

В разделе целей счётчика создать цели типа «Целевое событие» с точными идентификаторами из таблиц. Просмотры и реальные завершения должны оставаться отдельными целями. Перезагрузка, повторное открытие успеха и возврат из настроек отправляют `v4_success_view`, но не `v4_setup_complete`. Новое успешное завершение после изменения настроек может повторно отправить финальную конверсию; для конверсии людей использовать посетителей или визиты, а не сумму достижений.

## Полная карта событий

Все события имеют параметры `product=campaign_v4`, `schema=1`. На шагах оформления автоматически добавляется `step`, если место вызова не указало его явно. Идентификаторы стабильные, названия кнопок и тексты пользователя в них не участвуют.

### Лендинг и просмотры

| Идентификатор | Когда отправляется | Параметры |
|---|---|---|
| `v4_landing_view` | Открытие маршрута лендинга | — |
| `v4_section_view` | Раздел вошёл в центральную область экрана, один раз за открытие лендинга | `section`: hero, metrics, how, where, final |
| `v4_cta_click` | Нажатие запуска, включая вложенную иконку кнопки | `source`: hero, header, how, where, final |
| `v4_navigation_click` | Раздел, вход или документ | `target`, для входа и документов также `source` |
| `v4_placement_select` | Выбор другого размещения | `placement`: main, showcase, paid, rest |
| `v4_business_view` | Открыт первый шаг формы | `step=business`, `resumed` |
| `v4_details_view` | Открыты данные компании и точки | `step=details`, `resumed` |
| `v4_offer_view` | Открыт редактор, включая первую генерацию | `step=offer`, `resumed` |
| `v4_audience_view` | Открыт выбор клиентов | `step=audience`, `resumed` |
| `v4_success_view` | Открыт допущенный проверкой экран успеха | `step=success`, `resumed` |
| `v4_login_view` | Вход открыт именно из V4 | — |
| `v4_document_view` | Открыта оферта или обработка данных | Документ различается по виртуальному URL |

### Компания и качество ввода

| Идентификатор | Когда отправляется | Параметры |
|---|---|---|
| `v4_flow_start` | Первый фокус в поле за открытие процесса, включая восстановленный | `step`, `resumed` |
| `v4_field_error` | Попытка продолжить с ошибками | Первый ошибочный `field`, категория `reason`, число ошибочных полей `error_count` |
| `v4_lookup_start` | Начат поиск после проверки ИНН и телефона | `step=business` |
| `v4_lookup_result` | Получен результат существующего поиска | `result=success`, `method=lookup` |
| `v4_lookup_cancel` | Поиск прерван кнопкой или уходом до результата | `step=business` |
| `v4_identify_complete` | Переход к данным компании | `method`: lookup или manual |
| `v4_company_change` | Подтверждён новый ИНН вместо прежнего | Значение ИНН не передаётся |
| `v4_address_change` | Добавление или удаление точки | `action`: add/remove, `address_count` |
| `v4_business_mode` | Переключён режим онлайн | `online` |
| `v4_business_complete` | Данные компании приняты при продолжении | `online`, `address_count` |

Поиск сейчас использует профиль прототипа. Поэтому `v4_lookup_result` не доказывает получение сведений из реестра, а `v4_identify_complete` не является подтверждением личности или полномочий. При подключении реального поиска события нужно сохранить в ветках фактического результата и ошибки.

### Оффер и помощник

| Идентификатор | Когда отправляется | Параметры |
|---|---|---|
| `v4_generation_start` | Первая сборка или «Собрать заново» | `generation`: first/rebuild, признаки наполнения оффера |
| `v4_generation_complete` | Таймер завершён или пользователь показал результат | `generation`, `method`: automatic/skip, `duration_ms` |
| `v4_generation_leave` | Уход назад до готовности | `generation`, `duration_ms`; при возврате генерация может продолжиться |
| `v4_offer_edit` | Открытие или закрытие ручных настроек | `action`: open/close |
| `v4_offer_field_change` | Поле ручной настройки изменено и потеряло фокус | `field`: title/promo/discount/until, без значения |
| `v4_upload_result` | Файл принят после декодирования или отклонён | `field`: image/logo, `result`, `reason`: type/size/decode при ошибке |
| `v4_assistant_request` | Отправлена непустая команда | `method`: text/example/voice |
| `v4_assistant_result` | Правка применена или не поддерживается | `method`, `result`, `reason=unsupported` при отказе; при успехе `tone`, `has_discount`, `has_promo` |
| `v4_assistant_undo` | Пользователь отменил применённую правку | — |
| `v4_voice_start` | Попытка включить диктовку | `step`: offer/audience |
| `v4_voice_result` | Распознавание завершено, недоступно или выдало ошибку | `result`: success/empty/error, `reason`: unsupported/recognition |
| `v4_offer_complete` | Валидный оффер принят при продолжении | `tone`, `has_image`, `has_logo`, `has_promo`, `has_discount` |

Чат и генерация пока локальные. Эти события измеряют взаимодействие с текущим интерфейсом, а не качество ответа реальной модели. `duration_ms` — прошедшее время, включая ожидание вне активного окна; это не активное время вычислений.

### Клиенты и сохранение

| Идентификатор | Когда отправляется | Параметры |
|---|---|---|
| `v4_audience_select` | Выбран другой вариант фильтра | `group`: geography/gender/age/income/moment, `choice`: 0/1/2 |
| `v4_wishes_change` | Изменены дополнительные пожелания, поле потеряло фокус | Только `has_wishes` |
| `v4_save_start` | Финальная проверка пройдена, начинается сохранение | `step=audience` |
| `v4_save_result` | Завершилась финальная запись | `result`, `reason=storage` при ошибке |
| `v4_setup_complete` | Запись финальных настроек успешна | Признаки оффера, `online`, `address_count`, `has_wishes`, `resumed` |

Индексы фильтров: geography — рядом / город / Россия; gender — любой / женщины / мужчины; age — любой / 18–34 / от 35; income — любой / средний / выше среднего; moment — любой / переезд / зарплата. Это выбранные настройки кампании, а не характеристики самого посетителя.

### Возвраты и технические препятствия

| Идентификатор | Когда отправляется | Параметры |
|---|---|---|
| `v4_draft_restore` | Завершилось чтение локального черновика | `result`: success/empty, `resumed`, сохранённый `step` |
| `v4_draft_error` | Не удалось прочитать черновик или запись перешла в ошибку | `result=error`, `reason=storage`; повторные ошибки записи не спамят до успешной записи |
| `v4_step_leave` | Уход с шага на другой отслеживаемый маршрут или наружу | `step`, `duration_ms` |
| `v4_step_back` | Возврат кнопкой или индикатором к более раннему шагу | `step`, `target_step` |
| `v4_route_blocked` | Прямая ссылка пыталась пропустить обязательные данные | `step` шага исправления, `reason=invalid` |
| `v4_flow_exit` | Явный выход через шапку или кнопку «Готово» | `source`, `target=landing`, при выходе из мастера также `step` |

Закрытие вкладки не отправляет отдельную «конверсию отказа»: такое событие ненадёжно. Потери рассчитываются по отсутствию следующего шага в пределах визита. Кнопки Back/Forward браузера создают просмотры и `step_leave`; событие `step_back` относится к кнопкам самого интерфейса.

## Источники и данные

Виртуальные просмотры используют канонические URL вида `/#/v4/create/offer`, без пользовательских query-параметров. Внешний referer сокращён до домена. Для атрибуции сохраняются только `utm_source`, `utm_medium`, `utm_campaign`, `utm_content`, `utm_term`, `yclid` из query до hash, с буквами, цифрами и символами `_.~-`, длиной до 100. В UTM нельзя помещать контактные данные; пробелы и неподдерживаемые значения отбрасываются.

ИНН, телефон, имя и название компании, сайт, город, адреса, заголовок, размер скидки, промокод, дата акции, тексты пожеланий, чата и речи, имена и содержимое файлов не входят в payload событий. Вебвизор выключен, форма дополнительно помечена `ym-hide-content` и `ym-disable-keys`. Метрика при активации счётчика всё равно обрабатывает собственные технические данные визита; публикацию документов по аналитике нужно завершить отдельно.

Допустимые параметры фильтруются повторно в одном модуле: строки только из перечислений, флаги только boolean, числовые метрики ограничены диапазонами. Ошибки содержат категории, а не текст исключения. Исключение или блокировщик Метрики не прерывают оформление. Ограничения браузера и блокировщики означают, что эти данные нельзя считать учётом всех сохранений.

## Отчёты и разрезы

- Главная воронка по визитам и уникальным посетителям; отдельные сегменты новых и восстановленных открытий по `resumed`.
- Конверсия по источникам, UTM, устройствам и браузерам; вклад CTA через `source`.
- Где теряются пользователи: просмотр шага → его завершение; отдельно первые ошибки по `step`, `field`, `reason`.
- Работа с оффером: доля повторных сборок, пропуск ожидания, длительность, ручные правки, успех помощника, откаты, попытки голоса и ошибки загрузки.
- Выбор клиентов: доли географий и фильтров, использование пожеланий; эти параметры не смешивать с демографией посетителей Метрики.
- Надёжность: `save_start` → `save_result success` → `setup_complete`, доля ошибок хранения и заблокированных переходов.

## Приёмка

Локальная проверка 9 ноября 2026: 61 запись в диагностическом потоке, включая просмотры; подтверждён 31 из 45 типов событий. После финального сохранения — одна конверсия и три просмотра успеха с учётом перезагрузки и повторного входа. Источник hero передан корректно. Тестовые контактные данные, адрес, название, промокод, переписка, пожелания и имя файла в журнал не попали. Скрипт счётчика не загружался. Проверки компоновки на 390 и 1440 px прошли, ошибок браузера не было.

Проверены ручной ввод, ошибка обязательного поля, смена компании, пропуск генерации, ручная правка, отказ и успех помощника, отмена правки, неверный и правильный тип загрузки, выбор клиентов, пожелания и сохранение. Реальный микрофон, получение событий аккаунтом Яндекса и ошибка диска в браузере не воспроизводились. Тесты покрывают очистку параметров, UTM, повторные эффекты, очередь до первого просмотра, возвраты, отсутствие конверсии от просмотра успеха и сбой транспорта. Docker Compose проверен через `config --quiet`, образы в этом проходе не собирались.

Материалы проверки: [поток событий](../output/metrika-v4-2026-11-09/events.json), [успешное завершение сценария](../output/metrika-v4-2026-11-09/flow-success.png).

1. Включить локальный debug и пройти лендинг → контакты → данные → генерация → оффер → клиенты → успех. Убедиться в правильном порядке и единственной финальной конверсии.
2. Повторно открыть или перезагрузить успех: появляется новый просмотр успеха, но нет новой финальной конверсии.
3. Проверить пустые поля, ручной ввод, отмену поиска, повторную генерацию и пропуск ожидания, правку из примера, неизвестную команду и отмену правки.
4. Проверить изменение фильтров и пожеланий; в JSON не должно быть содержимого полей.
5. Ввести тестовые ИНН, телефон и произвольные тексты. Проверить весь диагностический журнал на отсутствие этих значений.
6. Без номера счётчика и на localhost убедиться, что `mc.yandex.ru/metrika/tag.js` не загружается.
7. После получения номера: создать цели, пересобрать web и на тестовом публичном домене проверить фактическое поступление событий в Метрику. До этого проверена только разметка и локальный транспорт, а не получение данных аккаунтом.
