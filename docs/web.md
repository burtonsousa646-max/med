# Интерфейс кабинета

Код — `web/`: Vite 8, React 19, React Router 8, TanStack Query 5, openapi-fetch, Motion, Recharts, Lucide. Стили — `web/design-system/` (токены и компоненты `bl-`, шрифт Beeline Sans Regular), экранные стили — `web/src/app.css`. Экраны перенесены из прототипа `prototype-app/` и переведены на API платформы.

## 1. Как интерфейс ходит в API

- Типы запросов и ответов генерируются из `api/cabinet.yaml`: `npm run api:types` → `web/src/api.gen.ts` (руками не править). Поменяли контракт — перегенерируйте типы, иначе `npm run check` покажет расхождения.
- Клиент — `web/src/api.ts`: хуки чтения на Suspense (`useCompany`, `useCampaign`, `useBalance`…), после любого изменения перечитывается всё на экране, ошибка показывается тостом с `message` от сервера.
- Деньги приходят копейками строкой: `kop()` переводит в рубли для показа, `toKop()` — обратно для запроса.
- Поля ввода и ползунки сохраняются через 400 мс после последнего изменения (`useLater`).
- Пока кампания ждёт оплату или проверяется, экран опрашивает её раз в 1,5 с: статус двигает воркер.
- Кнопки, создающие платёж, передают ключ идемпотентности: повторное нажатие не создаст второй платёж.

## 2. Экраны

| Адрес | Экран | Доступ |
|---|---|---|
| `/login` | вход: бизнес-ID (Госуслуги, СберБизнес ID, Альфа ID) или код на почту | все |
| `/onboarding` | выбрать компанию или добавить по ИНН | вошедший без компании |
| `/invite/:token` | принять приглашение | вошедший |
| `/cabinet` | развилка после входа: согласия или кампании | партнёр |
| `/consent` | реквизиты, точки, согласия, проверка по ЕГРЮЛ | партнёр |
| `/c/:id/reach` | охват по точкам и прогноз | партнёр |
| `/c/:id/build` | сборка: автопилот, вручную, медиаплан, спецпроект; текст, картинка, ссылка | черновик или отклонённая |
| `/c/:id/checkout` | оферта и оплата недостающего, или ссылка руководителю | партнёр |
| `/approve/:token` | подтверждение руководителем | подписант той же компании |
| `/c/:id/launch` | оплата, проверка, маркировка, показ; исправление отклонённого текста | партнёр |
| `/cab/campaigns` | список, пауза | партнёр |
| `/cab/stats/:id` | статистика кампании (показы и клики — с модулем показа, день 3) | партнёр |
| `/cab/connections` | постбэк и CSV (день 3) | партнёр |
| `/cab/balance` | баланс, пополнение СБП, картой или счётом, операции | партнёр |
| `/cab/docs` | документы, ЭДО, приглашение бухгалтера | партнёр |
| `/cab/company` | реквизиты, точки, люди и доступ, согласия | партнёр |
| `/admin` | вход сотрудника; экраны бэкофиса — день 4 | сотрудник |

Невошедший на любом экране кабинета попадает на `/login?next=<экран>` и после входа возвращается туда же: адрес возврата проходит через сервер (`next` в `/auth/start`), чужие адреса сервер не принимает.

## 3. Что изменилось относительно прототипа

| В прототипе | Здесь |
|---|---|
| демо-компания по cookie, переключатель «руководитель / сотрудник» | настоящий вход; кто подписант — из компании |
| вход по телефону с кодом-заглушкой | код на почту (`/auth/email/*`) |
| охват «без входа по ИНН» | ИНН — после входа по почте, `/onboarding` |
| `Session.clock` — «48 часов / 2 недели» в статистике | статистика будет по событиям (день 3) |
| оплата — анимация QR и пауза | страница шлюза (заглушка `/api/stub/pay`) и возврат на запуск |
| картинка объявления — одна из трёх предустановленных | загрузка своей картинки; без неё — предмет-заглушка |
| смена типа оффера в черновике | тип выбирается при создании |
| `HashRouter` (`#/c/1`) | обычные адреса; на сервере нужен возврат `index.html` на неизвестные пути |

Лендинги и витрина «лучшее рядом» остались в прототипе. Витрина переедет как настоящая поверхность на модуле показа (день 3).
