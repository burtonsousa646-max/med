# ADR 0006. Единый API веб-приложений платформы

## Контекст

По [ADR 0003](0003-api-gateway.md) Gateway выбирает OpenAPI приложения по префиксу `/api/<app>`. Лендинг, кабинет и бэкофис сейчас используют отдельные префиксы для подсказок и флагов. Campaign Launcher использует одну модель черновика с гостевыми и авторизованными операциями. Мы хотим публиковать общие операции один раз и сохранить отдельные наборы флагов для веб-приложений по [ADR 0001](0001-feature-toggles.md).

## Варианты

### Вариант 1. Единый контракт и префикс /api

- **Плюсы:** единые пути для одинаковых ресурсов и общий набор типов запроса и ответа. Доступ задаётся политикой операции.
- **Минусы:** нужно обновить реестр Gateway, клиентские типы и тесты одновременно.

### Вариант 2. Сохранить префиксы приложений

- **Плюсы:** действующая регистрация Gateway и клиенты сохраняются без миграции.
- **Минусы:** общие операции публикуются под несколькими путями и требуют отдельных привязок.

## Решение

Человек согласовал вариант 1 и прямой переход: внешних потребителей старых маршрутов ещё нет. Новый рабочий контракт `api/openapi/platform.yaml` публикует операции под `/api/v1`. Маршруты страниц определяются фронтендом. Страницы личного кабинета остаются под `/app`.

- Campaign Launcher использует `/api/v1/campaign/drafts`. Гость работает с `/current` по защищённой cookie. Авторизованный пользователь обращается к `/{draftId}` по сессии, а сервис проверяет его авторство.
- Подсказки доступны под `/api/v1/suggestions` с прежними форматами и политиками доступа.
- `GET /api/v1/feature-flags/{web-app}` принимает идентификатор веб-приложения. Начальный перечень: `landing`, `app`, `backoffice`. Соответствие идентификатора и схемы флагов хранится в едином OpenAPI. Gateway возвращает только флаги из выбранной схемы. Неизвестный идентификатор допустимого формата получает 404. Идентификатор приложения не даёт полномочий и не меняет пользовательский контекст. Флаги вычисляются по подтверждённой сессии или без сессии по правилам ADR 0001.
- Общий префикс регистрируется явно и заменяет прикладные префиксы в одной поставке. Gateway сохраняет проверку соответствия операций и контроллеров при старте.

## Последствия

- Операции больше не дублируются при добавлении нового веб-потребителя общего API.
- В поставке T8 одновременно заменяются рабочие контракты, обработчики, сгенерированные типы, внутренние вызовы и тесты. После поставки прежние префиксы `/api/landing`, `/api/cabinet` и `/api/backoffice` возвращают 404.
- В этой же поставке правила выбора OpenAPI из ADR 0003 и маршрутизации выдачи флагов из ADR 0001 заменяются этим решением для веб-API. Unleash, правила вычисления флагов и проверки прав сохраняются.

## Когда пересмотреть

Если у веб-приложения появятся самостоятельные требования к версии или контракту, отдельно определить границы его API.
