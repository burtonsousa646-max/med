# Кампании, модерация, маркировка

Код — `server/modules/campaigns.ts`, `moderation.ts`, `marking.ts`; тесты — `campaigns.test.ts`; контракт — `api/cabinet.yaml` (тег «кампании»), `api/admin.yaml` (тег «модерация»).

## 1. Путь кампании

```
            ┌──── не подписант ────► approval ──── руководитель по ссылке ───┐
 draft ─────┤                                                                 ▼
            └──── подписант ──────► денег хватает или не нужны ──► moderation ◄── правка текста
                                    не хватает ──► invoice ── оплата ──┘    │         ▲
                                                                            ▼         │
                                          стоп-слово / отказ модели ──► rejected ─────┘
                                          нужен человек ──► ручная очередь
                                          одобрено ──► ОРД: erid ──► live ⇄ paused
```

| Статус | Что значит | Что можно менять |
|---|---|---|
| `draft` | черновик | всё |
| `approval` | сотрудник отправил руководителю, ссылка живёт 3 дня | ничего |
| `invoice` | ждёт оплату: шлюз или счёт | ничего |
| `moderation` | креатив на проверке или маркировке | ничего |
| `rejected` | текст или картинка не прошли | всё; новый текст — снова на проверку |
| `live` | показывается | название, места, широкая карточка, ставка, бюджет, дневной лимит, дата окончания, текст и картинка, пауза |
| `paused` | на паузе | то же |
| `finished`, `archived` | завершена, в архиве | ничего |

Правка в неподходящем статусе — 409 с перечнем полей. Чтобы не затереть чужую правку, интерфейс передаёт `version`: не совпала — 409.

## 2. Черновик

`POST /cabinet/campaigns { type }` создаёт черновик:
- условия — стартовые по типу оффера (купон «скидка 50 % на первый визит» и т. п.), партнёр меняет их в сборке;
- текст объявления — собран из условий и бренда компании;
- режим сборки — по сегменту: малый — автопилот, средний — вручную, крупный — медиаплан;
- место показа — «лучшее рядом», бюджет — минимальный (3 000 ₽), ссылка — сайт компании.

Проверки при правке: места показа существуют и активны; бюджет не меньше минимального; ставка не ниже минимальной ставки выбранных мест; ссылка начинается с `http(s)://`; текст — от 1 до 90 символов; сигналы существуют и продаются (`off` — нет).

Прогноз в ответе — оценка на месяц: охват по активным точкам и радиусу (порт `geo.reach`), доля людей по выбранным сигналам, цена клика — ставка или полторы минимальных (с наценкой широкой карточки), CTR — средний по местам, не больше 3 показов на человека в неделю. Точнее станет с подключением DMP.

## 3. Отправка

`POST /cabinet/campaigns/{id}/submit`. Общие условия: компания проверена, выбрано место показа, у перехода, заявки и промокода есть ссылка.

**Подписант** запускает сам:
1. Если действующая версия оферты не принята — нужен `acceptOffer: true`, иначе 422.
2. Деньги. Купон и подписка денег не требуют: платит абонент, партнёру — выплаты. Постоплата — только крупному бизнесу. Иначе считается, сколько не хватает на месячный бюджет: бюджет − (основной + бонусный баланс). Хватает — сразу на проверку. Не хватает — платёж на недостающее, не меньше минимального пополнения, кампания в `invoice`. Оплата дошла — кампания на проверке.
3. Повтор с тем же `idempotencyKey` не создаёт второй платёж.

**Не подписант** (сотрудник, владелец без права подписи) получает `approvalUrl` — ссылку `APP_URL/approve/<token>`; письмо уходит подписантам компании. Руководитель открывает ссылку, входит через бизнес-ID и подтверждает (`POST /cabinet/approvals/{token}/confirm`) — дальше как у подписанта. Ссылка открывается только подписанту той же компании, одноразовая, живёт 3 дня.

## 4. Креативы и версии

Креатив — текст и картинка. В черновике правится на месте. После отправки каждая правка — новая версия на проверку. Живая кампания показывает последнюю версию, которая одобрена **и** промаркирована (`liveCreative`); новая версия ничего не ломает, пока её проверяют. Отказ по новой версии не останавливает кампанию — партнёр получает письмо с причиной.

Картинка: `POST /cabinet/campaigns/{id}/image` (PNG, JPEG, WebP до 2 МБ) возвращает `imageKey`, затем `PATCH { imageKey }`. Файлы креативов публичны: `/api/files/creatives/…`.

## 5. Модерация

Задача на каждую версию креатива (`moderation_tasks`), проверка — в очереди воркера:

1. **Стоп-слова** из справочника `stop_words` (регулярные выражения). Совпадение — отказ сразу, причина для партнёра: «слово: закон. Например: вариант исправления».
2. **Модель** (порт `llm`). Отказ с уверенностью от 0,8 — отказ с причинами модели. «Нужен человек» или неуверенный отказ — ручная очередь. Иначе — одобрено.

Ручная очередь — `GET /admin/moderation` (роль moderator), решение — `POST /admin/moderation/{id}`; отказ без причины не принимается. Повторное решение — 409. Решения сотрудников пишутся в аудит.

Заглушка модели: текст про алкоголь (алкоголь, пиво, вино) — в ручную очередь, остальное — одобрено.

## 6. Маркировка

Одобренный креатив уходит в ОРД (порт `ord`, задача `ord.markCreative`): организация → договор (принятая оферта) → креатив → erid. Организация и договор регистрируются один раз на компанию и хранятся в `external_refs`. erid записывается в креатив, после чего кампания на проверке становится `live`. Креатив без erid не показывается.

Ежемесячная выгрузка статистики в ОРД (`ord.reportStats`) — вместе с показами, день 3.
