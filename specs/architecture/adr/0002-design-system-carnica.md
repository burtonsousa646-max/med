# ADR 0002. Дизайн-система Carnica из архивов .tgz в web/packages/design-system

## Контекст

В `tech-stack.md` и `structure.md` дизайн-система была открытым вопросом: «где лежат токены и базовые компоненты, решается отдельно», а пакет `web/packages/design-system` описан как «токены и компоненты на Vanilla Extract — пока вне рамок». Своей дизайн-системы у платформы нет.

Человек передал готовую дизайн-систему билайна — Carnica — в виде npm-пакетов архивами и решил подключить её. Состав поставки:

| Пакет | Версия | Что в нём |
|---|---|---|
| `@carnica/ui-kit` | `2.0.0-carnica-3830.0` | компоненты React, хуки, `ThemeProvider`, стили тем |
| `@carnica/themes` | `2.0.0-carnica-3830.0` | палитры, шрифты, отступы — исходники PostCSS (`.pcss`) |
| `@carnica/graphics` | `2.0.0-carnica-3830.0` | иконки и графика |
| `@carnica/utils` | `2.0.0-carnica-3830.0` | хуки и утилиты для компонентов |
| `@carnica/fork-react-qr-rounded` | `1.0.1` | форк компонента QR-кода |
| `@beef/react` | `2.0.0-carnica-3830.0` | базовые утилиты React, конфигурация PostCSS, Jest, webpack |
| `@beef/utils` | `2.0.0-carnica-3830.0` | общие утилиты, `axios`, `redux` |
| `@beef/conf` | `2.0.0-carnica-3830.0` | конфигурация сборки: Babel, webpack, ESLint 8, stylelint, TypeScript |
| `@beef/testing` | `2.0.0-carnica-3830.0` | настройка тестов: mock-сервер, Testing Library, `fetch` |

Особенности поставки:

- Пакетов нет в публичном реестре npm, лицензия `UNLICENSED`. Доступа к внутреннему реестру, где они публикуются, у платформы нет.
- Пакеты ссылаются друг на друга по версиям, которых нет ни в реестре, ни в поставке: `^2.0.0-carnica-3830.0`, `2.0.0-alpha.50`, `^1.3.0-alpha.7` и т. п.
- Человек передал архивы `.tar`. pnpm не читает несжатый tar, поэтому архивы сжаты в `.tgz` без изменения содержимого. Распаковывать пакеты и править их содержимое нельзя.
- Компоненты собраны: JavaScript (ESM и CJS) и CSS Modules (`styles.module.css`). В готовом CSS остаются `@custom-media` и условия `@media (--touch-screens)` и подобные: для них нужна обработка PostCSS. Исходники тем в `@carnica/themes` — `.pcss` с `@mixin` и `@import`; выбранный ниже способ подключения их не использует.
- Тема передаётся компонентам через контекст React (`ThemeProvider` из `@carnica/ui-kit`).
- `@beef/conf` и `@beef/react` объявляют инструменты сборки и тестов — webpack, Babel, Jest 27, ESLint 8, stylelint, lerna (peer) — в `dependencies`, а не в `devDependencies`. Поэтому они ставятся вместе с дизайн-системой: +~1660 пакетов в `pnpm-lock.yaml`.

Ограничения платформы:

- стили платформы — Vanilla Extract, значения только из токенов (`ai/rules/frontend.md`, раздел «Стили»);
- host и module делят в одном экземпляре только пакеты из пресета `@platform/web-config/vite` (`ai/rules/architecture.md`);
- новые зависимости — только из стека или через ADR, install-скрипты разрешаются явно в `allowBuilds`, критические уязвимости исправляются до выкладки (`ai/rules/security.md`).

## Варианты

### Вариант 1. Архивы .tgz в репозитории, подмена через overrides pnpm

Архивы лежат в `web/packages/design-system/`. `overrides` в `pnpm-workspace.yaml` направляют все девять имён на архивы — и прямые зависимости приложений, и ссылки пакетов друг на друга. Приложение ставит нужный пакет `@carnica/*` или `@beef/*` у себя и импортирует его напрямую.

- **Плюсы:**
  - работает без доступа к внутреннему реестру и без сети для этих пакетов;
  - содержимое поставки не меняется; `pnpm-lock.yaml` хранит хеш каждого архива, подмена файла видна при установке;
  - в коде те же имена пакетов, что в документации Carnica; при переходе на реестр меняются настройки получения пакетов, а импорты сохраняются.
- **Минусы:**
  - бинарные архивы в git, ~1,5 МБ на каждую версию поставки;
  - обновление — вручную, по процедуре ниже;
  - `overrides` действуют на весь workspace: другой версии этих пакетов в репозитории быть не может.

### Вариант 2. Внутренний реестр npm билайна

Пакеты ставятся из реестра, где их публикует команда Carnica, через `.npmrc` с адресом и токеном.

- **Плюсы:** обычное обновление версий, нет архивов в git, не нужны `overrides` для ссылок пакетов друг на друга.
- **Минусы:** доступа к реестру сейчас нет; токен реестра нужен на каждой машине разработчика и в CI; версии, на которые ссылаются пакеты (`2.0.0-alpha.50` и др.), в реестре тоже могут отсутствовать.

### Вариант 3. Распаковать пакеты в workspace

Содержимое архивов лежит каталогами `web/packages/carnica-*` как пакеты workspace, зависимости между ними — `workspace:*`.

- **Плюсы:** не нужны `overrides`, видно содержимое в diff.
- **Минусы:** распаковывать поставку запрещено; в git попадают тысячи собранных файлов; любое обновление — огромный diff; появляется соблазн править чужой код.

### Вариант 4. Своя дизайн-система на Vanilla Extract

Токены и базовые компоненты платформа пишет сама, как было задумано в `structure.md`.

- **Плюсы:** один способ стилей на всю платформу, никаких лишних зависимостей.
- **Минусы:** дублирует существующую дизайн-систему билайна, интерфейс платформы будет отличаться от остальных продуктов; большой объём работы до первого экрана.

## Решение

На текущем этапе используем **вариант 1 — поставку как есть**: девять архивов, служебный пакет и подмена зависимостей через `overrides`. По решению человека доработки графа зависимостей, стилей, токенов и Module Federation откладываются. Известные ограничения зафиксированы ниже; подключение к приложениям этим решением не считается проверенным.

### Устройство

```
web/packages/design-system/            @platform/design-system — хранилище поставки, кода нет
  package.json                         зависимости file:./<архив>.tgz — ставит всю поставку
  ui-kit-2.0.0-carnica-3830.0.tgz      архивы как переданы, только сжаты в .tgz
  …
pnpm-workspace.yaml
  overrides:                           все 9 имён → file:web/packages/design-system/<архив>.tgz
  allowBuilds:                         core-js, core-js-pure, nx — запрещены
```

1. **Архивы** лежат в `web/packages/design-system/` под именами, которые даёт `pnpm pack`: `<имя без скоупа>-<версия>.tgz`, у `@beef/*` — с префиксом `beef-`. Архивы не распаковываются и не меняются.
2. **`@platform/design-system`** — служебный пакет: хранит все девять архивов в `dependencies` и гарантирует установку поставки целиком. Кода и экспортов у него нет; приложения используют пакеты Carnica напрямую.
3. **`overrides`** в `pnpm-workspace.yaml` направляют все девять имён на архивы. Без них pnpm ищет в реестре версии, на которые пакеты ссылаются друг на друга, и падает.
4. **Подключение в приложении.** Host или module ставит нужный пакет у себя в `dependencies` с точной версией поставки — `"@carnica/ui-kit": "2.0.0-carnica-3830.0"` — и импортирует его напрямую: `import { Button } from '@carnica/ui-kit'`. `overrides` подменяют версию на архив. Обёрток над компонентами и экспорта токенов платформы нет.
5. **Install-скрипты.** Скрипты `core-js`, `core-js-pure` (сообщения о спонсорстве) и `nx` (приходит как peer `lerna` у `@beef/conf`, платформе не нужен) запрещены в `allowBuilds`.
6. **Стили.** Используются CSS Modules из поставки. Дополнительная обработка custom media, общий контракт токенов и подключение темы в host пока не реализуются. Эти ограничения учитываются при первой интеграции в приложение; собственные стили платформы остаются на Vanilla Extract по действующим правилам.
7. **Код дизайн-системы не правится.** Ошибка в пакете исправляется новой поставкой от команды Carnica, а не патчем.

### Границы текущего решения

- Архивы и их содержимое не меняются; текущие зависимости сохраняются. Удаление `lerna`, исправляющие переопределения версий и `packageExtensions` сейчас не добавляются.
- Новые зависимости PostCSS, экспорт `@platform/design-system/tokens` и дополнительные singleton-пакеты в пресете Vite сейчас не добавляются.
- Сохраняются известные несовпадения peer, зависимость от скрытого hoist для `@babel/runtime` и уязвимости текущего графа. Это решение не вводит исключение из правила безопасности: критические уязвимости необходимо исправить до выкладки.
- Применение компонентов к реальным экранам требует проверки темы, адаптивности, порталов и React 19. Подключение темы и передача контекста между host и module определяются при первой интеграции, до её признания готовой.

### Отложенные улучшения

Следующие варианты сохраняются для отдельного решения, без обязательства реализовать их в текущем изменении:

1. Получить новую поставку с инструментами разработки в `devDependencies` и полными runtime-зависимостями; до неё рассмотреть точечное исправление графа зависимостей платформы.
2. Обрабатывать готовый CSS через `postcss-custom-media` с `preserve: false` в общем пресете Vite и Storybook. Альтернатива — компиляция `.pcss` с полным набором плагинов Carnica. Проба минимального преобразования описана в результатах проверки.
3. При необходимости добавить типизированный контракт Vanilla Extract поверх CSS-переменных Carnica и общие брейкпоинты. Состав и место экспорта определить отдельно; сейчас такого API нет.
4. Проверить singleton для `@carnica/ui-kit`, `@carnica/utils`, `@beef/react` на настоящем host и remote. Сейчас пресет разделяет только уже существующий набор библиотек; Carnica в него не добавлена.

### Обновление поставки

1. Человек получает новые архивы от команды Carnica. Если это `.tar` — сжимает в `.tgz` без распаковки: `gzip -n -c <файл>.tar > <имя>-<версия>.tgz`.
2. Старые архивы удаляются, новые кладутся в `web/packages/design-system/` под именами по пункту 1 «Устройства».
3. Новые имена файлов прописываются в `web/packages/design-system/package.json` и в `overrides` в `pnpm-workspace.yaml`; точная версия — в `dependencies` приложений, которые используют пакеты.
4. `pnpm install`, затем проверяется:
   - `pnpm-lock.yaml`: что добавилось и удалилось, не изменились ли версии пакетов вне дизайн-системы;
   - `pnpm peers check` — новые несовпадения сравниваются с принятыми в «Рисках»;
   - `pnpm ignored-builds` — новые install-скрипты разрешаются или запрещаются в `allowBuilds` после проверки пакета;
   - `pnpm audit` — новые критические уязвимости;
   - `pnpm lint`, `pnpm typecheck`, `pnpm test`, `pnpm build` и визуальные тесты приложений, которые используют дизайн-систему.
5. Коммит — `build(design-system): …` с версией поставки в описании. Изменения `pnpm-workspace.yaml` согласует архитектор.

## Последствия

- После принятия ADR дизайн-система закрывает открытый вопрос из `tech-stack.md`: базовые компоненты и тема — Carnica, а не своя разработка на Vanilla Extract.
- В приложениях появляется второй способ стилей: CSS Modules внутри компонентов Carnica. Код платформы его не использует — свои стили по-прежнему только на Vanilla Extract.
- В текущем lock-файле при сохранении поставки как есть +~1660 пакетов из графа Carnica: webpack, Babel, Jest 27, ESLint 8, stylelint, lerna, nx. Платформа ими не пользуется; при текущем подключении корневые `eslint`, `prettier`, `typescript` остались прежних версий, версии уже установленных пакетов не изменились. Установка дольше, `node_modules` больше.
- Попутно pnpm разрешил необязательные peer других пакетов на появившиеся `webpack`, `terser`, `yaml`: например, у `unplugin` и `unplugin-swc` теперь есть peer `webpack`. Версии пакетов от этого не меняются.
- Обновление дизайн-системы — ручная процедура с проверками, а не `pnpm update`.
- Переход на внутренний реестр потребует обновить `file:`-ссылки служебного пакета, `overrides`, `.npmrc` и lock-файл. Импорты приложений сохраняются; совместимость новой поставки проверяется повторно.

### Риски

| Риск | Что значит | Что делаем |
|---|---|---|
| `@carnica/fork-react-qr-rounded` ждёт `react`, `react-dom` 17.x и `react-redux` 7.x; у платформы React 19 | компонент QR-кода может не работать | сохраняется с проверкой: первая фича с QR-кодом проверяет его тестом и в Storybook; если не работает — новая поставка или другой компонент |
| `react-redux` 7 и `@reduxjs/toolkit` 1.9 (peer `@beef/conf`) ждут React до 18 | ставятся автоматически как peer, предупреждение `pnpm peers check` | сохраняется: платформа redux не использует |
| `ts-jest` 27 из `@beef/react` ждёт TypeScript < 5, у платформы 6 | Jest Carnica платформой не запускается | сохраняется, инструменты не запускаются |
| остальные несовпадения peer внутри поставки: пакеты ждут друг от друга `^1.3.0-alpha.*`, `stylelint` 15 вместо 14 или 16 | предупреждения `pnpm peers check` | сохраняются перечисленные несовпадения; используемые компоненты проверяются на стеке платформы |
| `pnpm audit`: 55 уязвимостей — 1 критическая (`tar`), 28 высоких; значительная часть приходит через инструменты сборки `@beef/conf` и `@beef/react` (lerna, nx, webpack, pug, postcss, stylelint) | инструменты сборки в сборку для браузера не попадают, но правило безопасности требует исправить критические до выкладки | сейчас сохраняются; исправление обязательно до выкладки |
| импорты `@babel/runtime` в собранном коде без объявленной зависимости | пакет находится только благодаря скрытому подъёму зависимостей pnpm (`hoist`) | сейчас сохраняется; устранение отложено, скрытый hoist пока необходим |
| CSS Modules компонентов и Vanilla Extract в одной сборке | порядок и пересечение стилей, размер CSS | проверяется на первом экране с компонентами Carnica |
| `axios` и `redux` в зависимостях `@beef/utils` | если компонент их использует, они попадают в сборку; `axios` в обход клиента API запрещён | платформа не вызывает `axios` и `redux` сама; запросы — только через `@platform/api-client` |
| архивы в git | репозиторий растёт на размер каждой поставки | сохраняется до появления доступа к реестру |

## Проверка текущей поставки

Проверка от 2026-11-17 выполнена на Node.js 24.22.2 и pnpm 12.16.1. Проект требует Node.js 26; повторение проверок на нём обязательно до завершения подключения.

- `pnpm install --frozen-lockfile --ignore-scripts` проходит: архивы доступны и согласованы с lock-файлом. Выполнение разрешённых install-скриптов этим запуском не проверено.
- `pnpm lint`, `pnpm typecheck`, `pnpm build` и 60 существующих модульных тестов проходят. Тесты с локальным HTTP-сервером требуют разрешения среды на открытие порта.
- Отдельная пробная ESM-сборка Vite с импортами `Button`, `Input`, `Checkbox`, `QRCode`, `ThemeProvider` и `@carnica/ui-kit/styles` проходит; типы импортов проверены. В итоговом CSS остаются custom media: успешная сборка не подтверждает корректную адаптивность.
- Дополнительная проба обработки собранного CSS через установленный `postcss-custom-media` с `preserve: false` устранила все определения `@custom-media` и ссылки вида `@media (--...)`, без предупреждений. Это подтверждает возможный способ преобразования; подключение плагина в пресет отложено, проверка в браузере не выполнена.
- В jsdom отрисованы перечисленные компоненты и проверен клик кнопки. Это не проверка внешнего вида в браузере и не гарантия совместимости всех компонентов с React 19.
- `pnpm peers check` завершается с ошибкой из-за несовпадений версий, перечисленных в рисках; отдельно есть несовпадение TypeScript 6 с `openapi-typescript`, не связанное с Carnica.
- `pnpm audit` сообщает 55 уязвимостей: 1 критическая, 28 высоких, 24 умеренных, 2 низких. Это снимок состояния зависимостей, а не постоянный результат.
- Приложений в `web/apps` пока нет. Внешний вид, адаптивность, порталы и передачу темы между host и module ещё предстоит проверить.

## Что входит в текущее изменение

- [x] `web/packages/design-system/` — девять архивов и служебный `package.json` без кода и экспортов.
- [x] `pnpm-workspace.yaml` — подмена девяти пакетов архивами и запрет install-скриптов `core-js`, `core-js-pure`, `nx`.
- [x] `pnpm-lock.yaml` — зафиксирован граф зависимостей текущей поставки.
- [x] Этот ADR — способ установки, результаты проверки и известные ограничения.

`tech-stack.md` и `structure.md` пока сохраняют прежнее описание дизайн-системы как открытого вопроса. Их уточнение, правила подключения темы и токенов, изменения пресетов и проверки первого приложения отложены вместе с интеграцией. До завершения подключения также нужно повторить проверки на Node.js 26 и установку с разрешёнными install-скриптами.

## Когда пересмотреть

- Появился доступ к внутреннему реестру npm с пакетами Carnica — переход на вариант 2.
- Новая поставка с инструментами сборки в `devDependencies` или с поддержкой React 19 в `@carnica/fork-react-qr-rounded`.
- Компоненты Carnica несовместимы с Vite, Module Federation или React 19 так, что это нельзя исправить настройкой сборки.
