# Адаптеры ролей

Роли команды описаны один раз — в `ai/agents/*.md`. Адаптеры позволяют вызвать роль командой в Claude Code, Codex, Kimi Code и Gemini CLI.

Адаптер — тонкая обёртка: он велит агенту прочитать файл роли и все правила из её поля `rules`, а затем выполнить задачу. Текст роли и правил в адаптер не копируется, поэтому изменение роли сразу действует во всех инструментах.

## Как вызвать роль

Имя роли везде одно — `id` из frontmatter файла роли. Префикс команды задаёт сам инструмент.

| Роль | Claude Code | Gemini CLI | Kimi Code | Codex |
|---|---|---|---|---|
| Аналитик | `/analyst` | `/analyst` | `/skill:analyst` | `$analyst` |
| Архитектор | `/architect` | `/architect` | `/skill:architect` | `$architect` |
| Frontend-разработчик | `/frontend-developer` | `/frontend-developer` | `/skill:frontend-developer` | `$frontend-developer` |
| Backend-разработчик | `/backend-developer` | `/backend-developer` | `/skill:backend-developer` | `$backend-developer` |
| Тестировщик | `/qa` | `/qa` | `/skill:qa` | `$qa` |

Задача пишется после команды:

```
/analyst опиши требования к пополнению баланса по прототипу
```

Без задачи роль спросит, что нужно сделать.

**Почему не везде `/имя`.** Codex не поддерживает свои слэш-команды в проекте: пользовательские команды в нём заменены навыками, которые вызываются через `$имя` или выбираются в `/skills`. Kimi Code вызывает навыки командой `/skill:имя`.

## Что генерируется

| Инструмент | Файлы | Как работает |
|---|---|---|
| Claude Code | `.claude/commands/<id>.md` | слэш-команда; `disable-model-invocation: true` — роль не запускается сама; `model` — по уровню роли из `ai/config/models.yaml` |
| Codex | `.agents/skills/<id>/SKILL.md` и `agents/openai.yaml` | навык; `allow_implicit_invocation: false` — только явный вызов |
| Kimi Code | `.agents/skills/<id>/SKILL.md` | тот же навык, что у Codex |
| Gemini CLI | `.gemini/commands/<id>.toml` | слэш-команда; задача подставляется в `{{args}}` |

Gemini CLI тоже видит навыки в `.agents/skills/` и может предложить включить роль сам — с подтверждением. Если это мешает, навык отключается командой `/skills disable <id>`.

## Модель

Уровень роли — поле `tier`: `reasoning`, `standard` или `fast`. Соответствие уровня модели — `ai/config/models.yaml`.

- **Claude Code** — модель записывается в команду, роль запускается на ней автоматически: аналитик и архитектор — `opus`, разработчики и тестировщик — `sonnet`.
- **Codex, Kimi Code, Gemini CLI** не умеют задавать модель в навыке или команде. Модель выбирается в инструменте перед вызовом роли; `models.yaml` подсказывает, какую.

## Где работает роль

Роль, вызванная командой, работает в основном диалоге, а не во вложенном агенте: так она может задавать вопросы и ждать согласования коммитов.

## Команды

| Команда | Что делает |
|---|---|
| `pnpm ai:adapters` | сгенерировать адаптеры по `ai/agents/` |
| `pnpm ai:adapters:check` | проверить, что адаптеры совпадают с ролями |

- После изменения `id`, `name`, `description`, `tier` или `rules` роли, изменения `ai/config/models.yaml`, а также после добавления или удаления роли — запустить `pnpm ai:adapters` и закоммитить адаптеры вместе с ролью.
- Адаптеры руками не правятся: в каждом есть пометка «Сгенерировано ai/adapters/generate.mjs».
- Генератор удаляет только свои файлы. Команды и навыки, добавленные вручную в те же каталоги, он не трогает.
- Генератор проверяет, что `id` совпадает с именем файла роли и что все правила из `rules` существуют.

## Новый инструмент

Чтобы подключить ещё один инструмент, в `generate.mjs` добавляется функция, которая строит файл адаптера из роли, и каталог в список `outputs`. Текст обёртки общий — функция `body`.
