# Партнёры

Код — `server/modules/partners.ts`, тесты — `partners.test.ts`, контракт — `api/cabinet.yaml` (теги «компания», «участники»).

## 1. Как компания появляется

| Путь | Кто становится кем |
|---|---|
| вход через бизнес-ID, провайдер подтвердил полномочия | владелец и подписант; компания создаётся по ИНН или находится существующая |
| вход по SMS, затем `POST /auth/companies { inn }` | владелец без права подписи; ИНН уже подключён — 409, нужно приглашение |
| приглашение владельца | сотрудник или бухгалтер |

## 2. Проверка юрлица

Сразу после появления компании в очередь ставится проверка (`partners.verify`):

| Ответ реестра (порт `companyRegistry`) | Статус |
|---|---|
| не найдена | `rejected`: «компания не найдена в ЕГРЮЛ» |
| ликвидирована или ликвидируется | `rejected` |
| высокий риск | `pending`, отметка «нужна проверка менеджером» |
| действует | `verified`; реквизиты (КПП, ОГРН, название, адрес) — из реестра |

Заодно компания ищется среди корпоративных клиентов билайна (порт `b2bCrm`: клиентский ID и менеджер), а проверенная заводится контрагентом в учётной системе (порт `accounting`). Оплата и запуск кампаний открываются только при `verified`.

## 4. Точки продаж

Адрес проходит геокодер (порт `geo`): не найден — 422. Хранятся и введённый адрес, и как его понял геокодер. Хотя бы одна точка остаётся в рекламе. Охват кампании считается от активных точек.

## 5. Приглашения

Владелец приглашает сотрудника или бухгалтера по почте: письмо со ссылкой `APP_URL/invite/<token>`, ссылка одноразовая, живёт 7 дней. Принять может любой вошедший человек со ссылкой (`POST /auth/invitations/{token}/accept`) — ссылка доказывает доступ к почте. Удалённый участник теряет сессии в этой компании сразу.

## 6. Оферта и согласия

- Действующая версия оферты — `settings.offer_version`. Принимает только подписант: в кабинете или при запуске кампании (`acceptOffer`). Принятие создаёт документ «оферта» и запись в аудите. Новая версия — нужно принять заново (`offerVersion` ≠ `currentOfferVersion`).
- Согласия: `company` — обработка данных компании, `signer` — данных подписанта, `profile` — использование профиля для подбора аудитории. Отзыв — `DELETE /cabinet/company/consents/{kind}`, история сохраняется.
