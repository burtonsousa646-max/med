# Безопасность

Что проверено и закрыто в день 4 и что остаётся до боя. Вход и роли — [auth.md](auth.md).

## 1. Что сделано

| Угроза | Защита | Где |
|---|---|---|
| чужая компания | компания и роль только из сессии; тест «чужая компания недоступна» | `identity.ts`, `identity.test.ts` |
| захват учётной записи по почте | учётные записи не склеиваются по почте от провайдера | [auth.md](auth.md#3-почему-учётные-записи-не-склеиваются-по-почте) |
| перебор кода входа | 5 попыток на код, повтор не раньше чем через минуту, 10 запросов в минуту с адреса | `identity.ts`, `security.ts` |
| утечка токенов из базы | в базе — SHA-256 токенов сессий, приглашений, ссылок руководителю, ключей постбэка | везде |
| подделка показа или клика | токен показа подписан HMAC (`SERVE_SECRET`), живёт 24 часа | `serving.ts` |
| поддельные события от систем | HMAC-подпись тела и уникальный ID события; в production без секрета — отказ | `hooks.ts` |
| двойное зачисление или списание | ключи идемпотентности, сумма проводок проверяется базой, событие и операция — в одной транзакции | `billing.ts`, `settlement.ts` |
| SQL-инъекции | только параметризованные запросы; динамические колонки — из белых списков | везде |
| XSS | React; в HTML документов и страниц заглушек — экранирование | `documents.ts`, `identity.ts`, `embed.js` |
| открытый редирект | после входа — только путь внутри интерфейса; клик — только на ссылку кампании | `identity.ts`, `tracking.ts` |
| выход за папку файлов | отдаются только ключи `creatives/…` без `..` | `index.ts` |
| залпы запросов | лимиты с одного адреса: вход 30, коды 10, действия в приложении 30, постбэк 1 200, публичный API 20 000 в минуту | `security.ts` |
| большие тела запросов | до 3 МБ | `security.ts` |
| заголовки | nosniff, запрет встраивания чужими сайтами, HSTS, Referrer-Policy | `security.ts` |
| бэкофис на открытом стенде | заглушка SSO выдаёт любые роли, поэтому в production требует код доступа `STUB_SSO_CODE`, без него закрыта | `identity.ts` |
| ключ постбэка в журналах | nginx не пишет в журнал адреса постбэка | `deploy/platform.nginx` |
| действия сотрудников | каждое — в `audit_log` | `backoffice.ts`, `billing.ts` |

## 2. Что остаётся до боя

| Что | Почему | Когда |
|---|---|---|
| политики строк PostgreSQL (RLS) | второй уровень изоляции компаний, если в коде ошибка | до первых реальных партнёров |
| лимиты и частота показов в Redis или nginx | сейчас счётчики в памяти одного процесса | со вторым экземпляром API |
| ключ постбэка в заголовке или подпись запроса | ключ в адресе может осесть в журналах партнёра | по просьбе первых партнёров с серверами |
| заглушки входа выключить | на стенде любой может войти как любая компания (`ALLOW_STUB_LOGIN=1`) | при подключении ЕСИА, Сбер и Альфа ID |
| шифрование секретов в базе | секретов в базе сейчас нет, только хеши; появятся с токенами OAuth CRM партнёров | с портом `partnerCrm` |
| требования ИБ билайна к контуру с ПДн | аттестация, журналирование доступа, хранение | при переезде в облако билайна |
| внешний тест на проникновение | | перед боем |
