# Оформление кампании MVP в Яндекс Метрике

Маршрут начинается на `/`. Финальная конверсия соответствует заявке, которую API принял на проверку и записал в базу. В кабинете партнёра и в кабинете сотрудника доступна одна и та же заявка. Доставку служебного письма отслеживает серверная очередь.

## Воронка для нового партнёра

В счётчике создайте JavaScript-цели с условием «идентификатор совпадает». В разделе «Отчёты» выберите «Создать отчёт → Воронка», назовите отчёт «Оформление кампании MVP» и добавьте шаги с условием «Достижение JS-цели» в порядке таблицы. Для первого отчёта можно взять окно 7 дней, чтобы учесть возврат к черновику. [Настройка воронок в Метрике](https://yandex.ru/support/metrica/ru/reports/funnels)

| Шаг | Идентификатор | Условие в интерфейсе |
|---|---|---|
| 1. Открыли лендинг | `mvp_landing_view` | Отобразился лендинг партнерской платформы билайн |
| 2. Начали оформление | `mvp_start_click` | Нажали кнопку запуска кампании на лендинге |
| 3. Запросили код | `mvp_code_sent` | Почтовый транспорт принял письмо с кодом |
| 4. Подтвердили почту | `mvp_email_verified` | Сервер проверил код, браузер получил авторизованную сессию |
| 5. Подтвердили компанию | `mvp_company_confirmed` | Сервер сохранил профиль с ИНН |
| 6. Открыли форму промокампании | `mvp_promo_view` | Авторизованный партнёр вошёл в редактор |
| 7. Нажали «Отправить на проверку» | `mvp_submit_attempt` | Форма прошла клиентскую проверку, оферта принята |
| 8. Заявка принята | `mvp_campaign_submitted` | Получено подтверждение отправки заявки |

Для вернувшихся партнёров соберите короткую воронку из шагов 6–8. Она учитывает вход сразу в редактор и повторное открытие черновика. Сравнивать стоит посетителей, поскольку один партнёр может создать несколько кампаний.

## Диагностика

| Идентификатор | Когда отправляется |
|---|---|
| `mvp_login_view` | Открылась форма входа |
| `mvp_company_view` | Партнёр открыл сохранённые реквизиты |
| `mvp_company_changed` | Сохранены реквизиты после выбора «Сменить компанию» |
| `mvp_cabinet_view` | Открылся кабинет партнёра |
| `mvp_formats_view` | Партнёр открыл выбор формата новой кампании |
| `mvp_upload_result` | Результат выбора фото, параметр `result` принимает `success` или `error` |
| `mvp_audience_mode` | Переключён режим аудитории, параметр `method` принимает `automatic` или `manual` |
| `mvp_terms_accepted` | Партнёр отметил согласие с офертой |
| `mvp_submit_error` | У попытки отправки возникла ошибка |
| `mvp_receipt_view` | Открылась сохранённая серверная заявка, включая повторное открытие из кабинета |

События содержат `product=campaign_mvp`. Маршрут квитанции передаётся как `/app/campaigns/detail`. В нём нет идентификатора заявки. Параметры финальной цели ограничены флагами онлайн-бизнеса и загрузки фото и числом точек. Свободный текст, контакты, ИНН, адреса, фотографии и одноразовые коды в разметку не передаются. Повторный просмотр квитанции учитывается отдельно от отправки.

## Проверка и публикация сотрудником

Воронка сотрудника использует цели `staff_queue_view` → `staff_submission_view` → `staff_review_saved` → `staff_offer_published`. Последняя цель срабатывает, когда API публикует предложение после проверки, указания erid и подтверждения оплаты. Повторное сохранение тех же отметок не создаёт ещё одну публикацию. Снятие предложения учитывает `staff_offer_withdrawn`. Параметр `product` равен `staff`.

## Витрина

Для посетителя соберите воронку `market_view` → `market_offer_open` → `market_code_reveal` → `market_partner_visit`. Для предложений без промокода уберите шаг его раскрытия. Дополнительные цели — `market_search`, `market_filter`, `market_more`, `market_code_copy` и `market_signup_click`. Переход с лендинга помечен `market_link_click`. Параметр `product` для этих событий равен `market`. Запросы поиска, промокод, erid, ID заявки и ссылки с ID предложения исключены из событий и виртуальных просмотров.

Партнёр, сотрудник и посетитель открывают сайт в разных сессиях. Для отчёта по пользователям соберите три отдельные воронки. Для подсчёта принятых и опубликованных заявок сопоставляйте `v4_submissions.id` с `market_publications.submission_id` внутри платформы.

## Проверка и подключение

Из каталога `prototype-app` на Node 22.18+ выполните `npm test`, затем `npx playwright install chromium` и `npm run test:mvp-browser`. Сквозной тест использует SQLite в памяти и тестовый почтовый транспорт. Он сверяет поля обоих кабинетов, очередь подтверждает интеграционный тест. На компьютере с установленным Chromium можно передать путь к браузеру в `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`.

Для ручной проверки событий на localhost используйте `VITE_METRIKA_DEBUG=true npm run dev`. Когда появится счётчик, укажите его публичный номер в `VITE_METRIKA_ID` при сборке web и создайте отчёт в аккаунте. На локальном адресе отправка в Яндекс отключена. Фактические достижения для созданных целей проверяются на домене счётчика. Блокировка аналитики браузером и потеря связи влияют на статистику, а все принятые заявки учитывает база.
