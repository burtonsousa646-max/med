# Подключение помощника офферов

Автоматическая сборка и чат используют `POST /api/v4/offer-ai`. Сервер читает [системный промпт](campaign-offer-rules.md) после первого разделителя Markdown. Ответ проходит проверку схемы и правил оффера. Идеи, уточняющие вопросы и ошибки не меняют черновик.

## Локальная проверка на ответах Codex

Из каталога `prototype-app` запустите демо-API и Vite в двух терминалах. Эти порты позволяют оставить основной локальный стенд открытым.

```sh
OFFER_AI_PROVIDER=codex-replay OFFER_AI_REPLAY_FILE=scripts/fixtures/offer-ai-codex.json API_PORT=8789 DB_PATH=:memory: npm run server
API_PORT=8789 npm exec -- vite --port 5186 --strictPort
```

Откройте `http://127.0.0.1:5186/#/v4` и создайте черновик. Введите категорию «Шиномонтаж», чтобы увидеть автоматический заголовок и уточняющий вопрос. Для проверки ручной правки задайте заголовок «Скидка 20% на замену резины» и скидку 20, затем отправьте «Сделай скидку 25%». Категория «Кофейня» показывает три идеи. Сценарии задаются в `scripts/fixtures/offer-ai-codex.json`. Для остальных запросов локальный режим использует базовые правила прототипа.

## Настройка API на проде

Задайте серверные переменные `OFFER_AI_PROVIDER=openai`, `OFFER_AI_MODEL` с доступной моделью, поддерживающей Structured Outputs, и `OPENAI_API_KEY` через секреты окружения API. Браузер вызывает прежний внутренний адрес. Ключ не передаётся клиенту. Режим `codex-replay` отключён при `NODE_ENV=production`.

В OpenAI уходят название и сфера бизнеса, данные оффера, текст правки и признаки наличия файлов. Сервер исключает отдельное поле с действующим промокодом, ИНН, телефон, адрес, URL сайта и сами файлы. Если партнёр введёт эти данные прямо в сообщение, они станут частью его запроса. API вызывается с `store: false`.

Сервер ограничивает число параллельных запросов и суточное число обращений на процесс. При ошибке редактор сохраняет текущие данные и предлагает повторить запрос. Значение `OFFER_AI_PROVIDER=off` оставляет встроенные правила прототипа. Ответ модели может запросить удаление фона у загруженного фото. Генерация новых изображений пока возвращает задание для отдельного инструмента. Импорт файлов с сайта и ручная загрузка доступны в редакторе.

## Обработка фотографий

Для фото в боковом макете редактор запрашивает альфа-маску, обрезает прозрачные поля и сохраняет обработанный файл для креатива. Исходник остаётся в локальном черновике. В «Редактировать» можно вернуть его или повторить обработку. В макете «Фото сверху» редактор сохраняет окружение на снимке.

На macOS соберите локальный обработчик Apple Vision из каталога `prototype-app` и перезапустите демо-API.

```sh
mkdir -p node_modules/.cache
swiftc scripts/offer-cutout.swift -o node_modules/.cache/med-offer-cutout
```

В Linux задайте `OFFER_CUTOUT_URL` на закрытый обработчик, который принимает multipart с полем `file` и возвращает PNG того же размера с альфа-каналом. Подойдёт внутренний маршрут `/api/remove` сервиса rembg с выбранной моделью. Обработчик запускается отдельно от языковой модели. Если он недоступен или маска не проходит проверку, редактор сохраняет исходное фото.
